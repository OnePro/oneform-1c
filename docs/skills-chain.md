# Новые объекты и формы: цепочка с навыками cc-1c-skills

Эксперимент (платформа 8.3.27.2342, формат выгрузки 2.20) о том, можно ли создать объект «с нуля» готовыми навыками
([cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills)), а обычную форму для него получить через `oneform`.

## Что проверено в живой 1С

| Шаг | Чем | Результат |
|-----|-----|-----------|
| Пустая обработка | `epf-init` + `epf-build` | собирается |
| Пустой отчёт | `erf-init` + `erf-build` | собирается |
| Обычная форма у обработки и у отчёта | `oneform clone-form` (донор — маленькая форма) + `epf-build` | форма открывается, все 152 свойства элементов совпадают с исходной формой |
| Пустая конфигурация и справочник | `cf-init` + `meta-compile` | загружается (`db-load-xml`, `db-update`) |
| Обычная форма нового справочника из чужой формы | `clone-form` с формой «Контрагенты» | загружается, но форма **не открывается**: модуль донора обращается к общим модулям и реквизитам УТ |
| Пустая форма нового справочника | клон «ФормаГруппы» → `extract`, удаление элементов и событий, пустой модуль → `pack` | открывается: остаётся только командная панель «ОК / Записать / Закрыть» |
| Добавление элементов в эту форму | подпись и поле через `Form.xml` → `pack` | в 1С координаты, размеры и заголовок совпадают с заданными |

Главный вывод: **обычную форму для нового объекта нельзя взять у чужого объекта как есть.** Тип основного реквизита
выбирается платформой по владельцу формы, но элементы, табличные части и модуль донора принадлежат донору. Рабочий
путь — клон небольшой формы, затем очистка (модуль, события, элементы) и наполнение через `Form.xml`.

## Ошибки `oneform`, найденные этим экспериментом

Все исправлены и закрыты тестами.

1. Удаление нескольких соседних элементов, первый из которых стоит в начале списка, давало «replacement ranges overlap».
   Фаззинг удалял по одному элементу и этого не видел.
2. Удаление **всех** записей счётного списка оставляло `{0,}` с лишней запятой. Парсер это пропускал, `pack` сообщал об
   успехе, а 1С отвечала «Ошибка формата потока». Теперь список пишется как `{0}`, а `pack` отвергает любой результат с
   пустым элементом списка.
4. Пустой `<ChildItems>` и пробелы внутри контейнера, оставшегося без элементов, считались изменением формы.
   Теперь пустой `<ChildItems>` равен отсутствующему.
3. Добавляемый элемент с `DataPath` вида `СправочникОбъект.ИНН` терял привязку без сообщения. Теперь `pack` отказывает с
   причиной.

## Что пока не умеет `oneform`

- **Привязать новый элемент к реквизиту объекта** (`СправочникОбъект.ИНН`). Для существующих элементов путь читается
  (имена берутся из метаданных объекта), но записать шаги пути (`{0,<uuid реквизита>}` или `{-N}` для стандартного) при
  добавлении нельзя: нужно передать упаковщику таблицу имён из метаданных объекта.
- Автоматически подготовить «пустую» форму одной командой (сейчас: `clone-form`, затем ручная очистка).

## Как повторить

`target/skillexp/` в рабочей копии (не в git) содержит скрипты запуска; их суть:

1. `epf-init`/`erf-init`, затем `oneform clone-form <каталог объекта> --from <форма> --name <имя>` (форма-донор лежит в
   каталоге объекта рядом с метаданными: `Forms/<имя>.xml` и `Forms/<имя>/Ext/Form.bin`);
2. `epf-build`; открыть собранную обработку своей загрузочной обработкой (`ВнешниеОбработки.Создать` /
   `ВнешниеОтчеты.Создать`, `ПолучитьФорму`) и снять свойства элементов (`scripts/1c-e2e/`).
3. Для справочника: `cf-init`, `meta-compile`, `clone-form`, `pack`, `db-load-xml`, `db-update`, затем открыть форму
   менеджером справочника (`Справочники.Имя.ПолучитьФорму`).
