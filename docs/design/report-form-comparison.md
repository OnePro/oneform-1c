## What a Configurator form for a report with a schema is

* Extension `343b4e00-…` exists **because** the report has a composition schema: the form carries the settings composer
  (`ОтчетОбъект.[b9754f01-….][0][1]` is `Настройки.Отбор`-style path through the object’s settings composer).
  A report without a schema may produce another extension; only the schema variant was seen.
* Controls `Результат`, `ДействияФормы`, `Отбор` are most likely generated by the Configurator’s report form wizard
  (the 60 standard column names such as `ЛевоеЗначениеДляПодробногоОтображенияЭлемента` are not typed by a user);
  `ПолеВвода1`, `Надпись1`, `Кнопка1` are the user’s. Not confirmed with a second sample.

## Minimal changes so that `new-form --kind report` equals a Configurator report form

1. A separate template `report.form.bin` (not the processor one), mined from this stream with a placeholder instead of the
   `TypeId` (`scripts/mine_blank_forms.py`), with: main attribute id 3 `ОтчетОбъект`, `FormExtension` 343b4e00 with its body
   `{2,1,{0,0},{0},1,1}`, size 520 × 300, caption `Отчет  <Объект>`, no `ТаблицаНоменклатуры`, the head counters (`7,2`).
2. Controls of a default Configurator report: `Результат` (id 1), `ДействияФормы` (id 2, `StdSubmenu` (10) + 11 flat buttons), `Отбор` table (id 7, 60 columns, links list `7 → {3},{0,b9754f01-…},{0},{1}`) — remove the `ОсновныеДействияФормы`
   panel of the processor template. Decide first whether `Отбор` belongs to every report form (needs one more sample: a form made
   by the wizard of a report without a schema and one with a schema but without user controls).
3. Take the enumeration tables of the root record (`26,0,2,{0,1,1},{0,7,1},…`) from the sample, not zeros; they must stay in
   step with the control ids (ids 1, 2, 4, 7 there; for a blank form 1, 2, 7).
4. Docs: the `report` row of the table in `docs/agent-guide.md` and the V3 item of `docs/todo.md` become “done” only after a live
   check in 1C (open the form of a rebuilt `.erf`); `ТаблицаНоменклатуры` in the `processor` template is a separate cleanup.
5. A guard that does not need a new template: `new-form --kind report` could refuse (or warn) when the object has
   `MainDataCompositionSchema`, because the processor-style form is not the form that the Configurator makes for it.

Not trivial and not safe to do blindly: items 1–3 require changing a binary template whose tab/enumeration tables are not decoded
by oneform; they were not implemented.
