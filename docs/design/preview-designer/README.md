# Превью обычных форм 1С: задание дизайнеру

## Что мы просим

> **Нарисуйте, как должна выглядеть каждая часть формы 1С в нашем превью, и объясните, как это собрать в HTML/CSS.**

Мы делаем инструмент для форм «обычного приложения» 1С (толстый клиент, 8.x). Он читает файл формы `Form.xml` и показывает **приближённую картинку формы в одном HTML-файле**. Сейчас эта картинка местами не похожа на настоящую 1С: многие свойства элементов (шрифты, цвета, рамки, кнопки, закладки, таблицы, значки) превью не учитывает. Вы делаете **эталон внешнего вида** и **точные инструкции**, а мы по ним правим код.

Знать 1С и наш код не нужно. Нужны: браузер (Edge/Chrome), редактор, HTML/CSS/SVG. Python нужен только если захотите проверять свою работу на настоящих формах.

## Что вы возвращаете (подробно — `05-what-to-return.md`)

| Файл | Что это |
|---|---|
| `style-sheet.html` | **Макет.** Один самодостаточный HTML-файл (без сети, открывается в Edge/Chrome): сверху 1–2 собранные типичные формы, ниже **лист образцов** — каждый класс элементов во всех состояниях и со всеми вариантами свойств из каталога. У каждого образца `data-xml="…"` с ID из каталога и подпись по-русски. Формат — `style-sheet.example.html` |
| `render-spec.md` | **Инструкции.** По каждому классу: структура HTML, CSS, таблица «если в XML …, то в HTML …» на каждое свойство, состояния, особые случаи. Заполняется по скелету `render-spec.skeleton.md` |
| `theme.css` | CSS из макета: переменные и правила темы |
| `screenshots/` | Снимки `style-sheet.html` (PNG) |
| `questions.md` | Что вам нужно от нас: дополнительные снимки настоящей 1С, неясности |

Вернуть нужно **папку целиком** (например, `response/`), отправьте ту же структуру обратно.

## Порядок работы (оценка 2–4 рабочих дня)

1. Прочитайте `01-how-1c-looks.md` и посмотрите пары в `04-gallery.md` (30 мин).
2. Просмотрите `02-property-catalog.md`: ID, колонки «Как выглядит в 1С» и «Что делает превью сейчас» (1 ч). Начинайте с классов, у которых больше всего строк «игнорируется» с высокой частотой (в каждом классе они идут первыми).
3. Если для решения нужен снимок 1С, которого нет, — запишите ID в `questions.md`, не ждите: рисуйте по справке и пометьте допущение.
4. Нарисуйте `style-sheet.html` и вынесите CSS в `theme.css`.
5. Опишите всё в `render-spec.md` (скелет не менять).
6. Проверьте себя: `python tools/check_spec.py --dir response/` и, по желанию, `tools/build_samples.py` на ваших CSS.
7. Отправьте папку.

## Что можно менять, что нельзя

Превью — **приближённая картинка** формы. Положение и размеры каждого элемента берутся из `Form.xml` (абсолютные координаты `Left/Top/Width/Height` в пикселях), и это не меняется.

* **Можно:** цвета, шрифты (из системных), рамки, градиенты, кнопки, закладки, таблицы, значки (инлайновый SVG или data-URI), заглушки, состояния (недоступно, только просмотр, выбрано).
* **Нельзя:** менять координаты, размеры и расположение; придумывать новый смысл свойств; подключать внешние шрифты, картинки и скрипты; нарушать одно-файловость HTML.
* Результат должен корректно выглядеть для подписей на русском и румынском (`ru`/`ro`).
* Термины 1С в каталоге объяснены; если непонятно — вопрос в `questions.md`.
