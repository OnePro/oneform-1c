# 05. Что вернуть: состав, структура, приёмка

## 1. Структура возвращаемой папки

```
response/
  style-sheet.html        # макет: собранные формы + лист образцов (один файл)
  render-spec.md          # инструкции по скелету render-spec.skeleton.md
  theme.css               # CSS темы, вынутый из style-sheet.html
  screenshots/            # PNG листа образцов (по разделам) и собранных форм
  questions.md            # вопросы и запросы эталонов
```

Лишних файлов быть не должно; изображения внутри `style-sheet.html` — только inline-SVG или `data:`-URI.

## 2. `style-sheet.html`

Один HTML-файл, открывается двойным щелчком в Edge/Chrome без сети. Порядок на странице:

1. **Собранные формы (1–2).** Типичные формы целиком, собранные из тех же кусочков и тех же CSS-классов, что и лист образцов: например, карточка справочника (подписи, поля с кнопками выбора, группа-рамка, панель закладок, нижняя полоса «OK / Записать / Закрыть») и список (командная панель, таблица, дерево, разделитель). Размеры и положение — как в снимках из `04-gallery.md` (см. `gallery/NN-*-1c.png`); это ориентир, не копия.
2. **Лист образцов.** По разделу на каждый класс элементов (порядок как в каталоге). В каждом разделе — образец на каждое состояние и **на каждый вариант каждого визуального свойства** (`bold` и не `bold`, `Frame`/`SingleLine`/`None`, `ChoiceButton` с разными видами значка, с отсутствующим свойством и т. д.). Свойства, которые вы решили не отображать, на листе не показываются, но перечисляются в `render-spec.md` с причиной.
3. **Аннотации.** Каждый образец — `<figure class="specimen" data-xml="…" data-state="…">` с `<figcaption>` по-русски (что показано и какое правило применено).
   * `data-xml` — ID из каталога через пробел; в `[]` значение, которое образец иллюстрирует: `InputField.Font[bold=true]`, `UsualGroup.BorderStyle[Frame]`, `InputField.ReadOnly[true]`, `Button.Caption[нет]` (свойства нет в XML), `Color.value[#3366FF]`.
   * `data-state` — `normal | hover | focus | disabled | readonly | selected | pressed | checked`.
   * Образец собирается теми же классами, что описаны в `render-spec.md` (структура HTML там — «истина»).
4. **Одно-файловость.** Весь CSS в `<style>`, значки — inline `<svg>` или `data:`. Никаких `<link>`, `@import`, `http(s)://`, `<script src>`. Скрипты не нужны (допустим небольшой скрипт без сети, например для переключения).
5. Работает в современном Edge и Chrome; ширина листа — до 1400 px.

Пример формата — `style-sheet.example.html`.

## 3. `render-spec.md`

Берётся `render-spec.skeleton.md` (его создаёт `scripts/gen_render_spec_skeleton.py`; в нём уже стоят ID всех свойств). **Заголовки и порядок разделов не менять.** Структура:

* `§0` Константы темы: 0.1 шрифты · 0.2 цвета (имена CSS-переменных) · 0.3 рамки/тени/скругления · 0.4 размеры · 0.5 значки (SVG целиком) · 0.6 правила для отсутствующих свойств · 0.7 общие состояния · 0.8 языки и длинные подписи.
* `§1` Общие структуры (`Font.*`, `Color.*`, `Border.*`, `Picture.*`, `Shortcut.*`): таблица `ID | условие | действие`.
* `§2…§25` — по разделу на класс (`InputField`, `LabelDecoration`, `Button`, …). В каждом пять подразделов:
  1. **Структура HTML** — точные теги и классы (блок кода).
  2. **CSS** — точные правила (блок кода), с переменными из §0.
  3. **Свойства → правила** — таблица `ID | условие | действие в HTML/CSS`, **по строке на каждый ID** класса из каталога. «Условие» — значение в XML (`true`, `Center`, `kind=style без value`, «нет тега»…); «действие» — CSS-свойство, добавляемый класс, атрибут или вложенный SVG. Если не отображается — слова `не отображать` и причина.
  4. **Состояния** — те, что бывают у этого элемента в 1С: селектор, отличия, ссылка на образец.
  5. **Особые случаи** — пустые подписи, узкие/низкие элементы, длинный текст, комбинации свойств.
* `§26` Что не охвачено и что вы предлагаете изменить.

Формулировка правил — «если в XML <тег>=<значение>, то в HTML …». Пример строки:

| ID | условие | действие в HTML/CSS |
|---|---|---|
| `InputField.Font` | `<Font bold="true"/>` | добавить класс `b` на `.val`: `.t-InputField .val.b{font-weight:bold}` |
| `InputField.Font` | `<Font italic="true"/>` | `font-style:italic` на `.val` |
| `InputField.Font` | нет тега | наследовать шрифт формы (`--font`) |

## 4. `theme.css`

CSS-переменные на `#canvas` (или `:root`) и общие правила темы ровно в том виде, как они стоят в `style-sheet.html`. Имена переменных совпадают с `render-spec.md` §0.2. Можно (и желательно) оставить существующие имена из `tools/assets/form_theme.css` (`--form-bg`, `--cmdbar-bg`, `--border`, `--sep`, `--tab-bg`, `--head-from`, `--head-to`, `--group-title`, `--scroll-bg`, `--font`) и добавить новые; определить также `--field-border` (сейчас нигде не задана — ошибка).

## 7. Приёмка (чек-лист — проверяем и мы)

Автопроверка: `python tools/check_spec.py --dir response/` (нужен только Python).

- [ ] Каждый ID из `02-property-catalog.md`, влияющий на вид, **либо** показан на листе образцов (есть `data-xml` с этим ID) **и** покрыт строкой в `render-spec.md`, **либо** в `render-spec.md` явно помечен `не отображать` с причиной.
- [ ] Все ID `Font.*`, `Color.*`, `Border.*`, `Picture.*` (общие структуры) получили правила в §1.
- [ ] Для каждого состояния, которое бывает у элемента (disabled, read-only, selected, checked, hover, focus, pressed), есть образец или явное «не показываем».
- [ ] `style-sheet.html` открывается офлайн (без сети), в Edge и Chrome; в нём нет внешних ссылок (проверяет `check_spec.py`).
- [ ] CSS в `theme.css` совпадает с `<style>` листа; переменные из §0 используются, а не дублируются числами.
- [ ] Правила в `render-spec.md` однозначны: по ним можно написать код без догадок (нет «примерно», «как в 1С»).
- [ ] (по желанию, но рекомендуется) Три образца форм из `tools/samples/` собираются с вашим CSS без поломки раскладки: `python tools/build_samples.py --overlay response/theme.css --screenshot`, затем посмотреть `tools/out/*.png` (поддерживаются только изменения CSS; нужная правка JS — в `questions.md`/§26).
- [ ] `questions.md` заполнен (может быть пустым разделом «нет»).

## 8. Ограничения (повторяем)

* Координаты и размеры элементов из `Form.xml` **абсолютные** и не меняются; CSS не должен их переопределять (`left/top/width/height`, `position` корневых `.c`), не добавлять элементам внешние отступы, смещающие содержимое.
* Результат остаётся **одним самодостаточным HTML** (в нашем коде CSS и JS вставляются в страницу). Внешние шрифты, картинки, CDN — нельзя; значки — inline SVG/data-URI.
* Стиль — «классика 1С» (плоский, 1 px рамки, кремовая палитра, как на снимках `gallery/`), а не современный; допустимы небольшие улучшения читаемости, если они не уводят от узнаваемости.
* Работа в Edge/Chrome; подписи русские и румынские (`ru`/`ro`), в том числе длинные.
