# Дорожная карта: Скилл ИИ-агента `oneform` и обратная компиляция `Form.xml -> Form.bin / .epf / .erf`

Дата фиксации: 2026-10-22.

## 1. Цель

Дать ИИ-агенту (и разработчику 1С) замкнутый цикл работы с обычными формами 1С 8.2 / 8.3 без ручного кликанья в Конфигураторе:

1. **Точечное извлечение (`oneform extract <path>`)** — за ~40 мс распаковать только нужный объект конфигурации (`Documents/ПоступлениеТМЦ`) или внешнюю обработку/отчёт (`.epf` / `.erf`) в `src/` (`Form.xml`, `Module.bsl`, `ObjectModule.bsl`, `FormPreview.html`).
2. **Генерация или модификация в `Form.xml` + `.bsl`** — агент меняет существующие элементы, добавляет новые поля/кнопки/колонки/страницы или создаёт новую форму с нуля исключительно через `Form.xml` и `.bsl`.
3. **Мгновенный визуальный контроль и согласование с клиентом (`oneform preview <path>`)** — рендер `FormPreview.html` 1:1 с Конфигуратором 1С (переключение вкладок и слоёв, проверка перекрытий, клик по кнопкам/колонкам, переход к BSL-процедурам).
4. **Обратная сборка в бинарник (`oneform pack <path>`)** — после подтверждения пользователем `oneform` компилирует `Form.xml` и `.bsl` обратно в `Ext/Form.bin` или `.epf` / `.erf`.

---

## 2. Архитектура обратной компиляции (`Form.xml -> FormStream.bin`)

Поток `form` внутри `Ext/Form.bin` и `.epf`/`.erf` — это сжатое raw-deflate UTF-8 скобочное дерево (`{27, {18, ...}}`). Чтобы гарантировать 100% валидность всех 50–70 служебных полей каждого элемента управления для Конфигуратора 1С, используется гибридный подход **AST-Patching + Вшитая форма-донор (`donor_form.bin`)**:

### Уровень 1: Патчинг существующих элементов по месту (AST-Patching)
Если у формы уже есть `Reference/FormStream.bin` и элемент с данным `id` / `name` и тем же типом уже существует:
- Берётся оригинальный узел элемента из `FormStream.bin`.
- Точечно обновляются изменённые в `Form.xml` свойства:
  - геометрия (`left`, `top`, `right = left + width`, `bottom = top + height`), `<Visible>`, `<ZOrder>`, `<TabOrder>`, индекс страницы `<Page>`;
  - `<Caption>`, `<Tooltip>`, `<ReadOnly>`, `<HorizontalAlign>`, `<Font>`, цвета, `<BorderStyle>`;
  - `<DataPath>` (в `root[2][3]`);
  - `<Events>` элемента, формы и колонок таблиц;
  - кнопки и подменю `<CommandBar>` (`X[7]`);
  - колонки `<Table>` (`width`, `visible`, `readOnly`, `Header`, `DataPath`, `Editor`, `Events`);
  - страницы `<Panel>` (`Title`, `Visible`, `Enabled`, `ShowTabs`).
- Все остальные служебные поля узла сохраняются без изменений.

### Уровень 2: Клонирование новых элементов из вшитой «Формы-донора»
В бинарник `oneform.exe` вшивается эталонный набор узлов-прототипов (донор), извлечённый из реальных форм, сохранённых Конфигуратором 1С:
- Все основные типы элементов управления (`InputField`, `CheckBox`, `RadioButton`, `ChoiceField`, `ListBox`, `LabelDecoration`, `PictureDecoration`, `UsualGroup`, `Button`, `CommandBar`, `Panel`, `Table`, `SpreadsheetDocumentField`, `TextDocumentField`, `HTMLDocumentField`, `Splitter`, `ProgressBar`, `TrackBar`, `CalendarField`, `Chart`).
- Прототипы колонок таблиц (`c2cf1953` для ТЧ, `737535a4` для `ValueTable`/`ValueTree`, `48a6ebc3` для списков) и вложенных `base64`-блобов ячейки редактора (`props[39]`).
- Прототипы действий и групп кнопок `CommandBar` (`Handler`, `Standard`, `Submenu`, `Separator`).
- Прототипы реквизитов формы (`String`, `Number`, `Boolean`, `Date`, `ValueTable`, `ValueTree`, `ValueList`, `SpreadsheetDocument`).

При появлении в `Form.xml` нового элемента без существующего узла в `FormStream.bin`:
1. Клонируется прототип нужного типа из донора.
2. Назначается свободный числовой `id` (с обновлением счётчика `nextFreeId` формы в `root[2][1]`).
3. Применяются все свойства из `Form.xml` по правилам Уровня 1.
4. Удалённые из `Form.xml` элементы вырезаются из таблицы детей, `ZOrder` и `links`.

### Уровень 3: Создание новой обработки (`.epf`), отчёта (`.erf`) или формы с нуля (`oneform init`)
- Команда `oneform init <path.epf|path.erf> [--kind processor|report] [--name <Имя>]` разворачивает из вшитого шаблона контейнера `.epf`/`.erf` и чистого корня формы-донора готовое дерево `src/`.
- Агент редактирует `Form.xml`, `Module.bsl`, `ObjectModule.bsl`, рендерит `FormPreview.html`, показывает пользователю и по `oneform pack` собирает готовый `.epf` / `.erf`.

## 3. Что делает `Form.xml` достаточным на 100% (без ручной правки `.bin`)

1. **Автогенерация `id` и привязок**: если агент не указал числовой `id` у нового элемента/колонки/кнопки/реквизита, компилятор `oneform pack` назначает его автоматически.
2. **Разрешение `<DataPath>` по имени**: агент может указать `<DataPath>ДокументОбъект.Курьер</DataPath>` или `<DataPath>ТаблицаТМЦ.Количество</DataPath>`, а компилятор сам находит `attributeId` и UUID реквизита в метаданных объекта (`Document.xml` / `Catalog.xml`) или в `<Attributes>` формы.
3. **Полнота модели `Form.xml`**:
   - Полная геометрия, иерархия `Panel/Page`, `ZOrder`, `TabOrder`, `ShowTabs`.
   - Полное дерево кнопок и вложенных подменю `CommandBar` с `actionKind`, `action` (BSL), `Tooltip`.
   - Полное описание всех 4 классов колонок `Table` (ТЧ, списки, `ТаблицаЗначений`/`ДеревоЗначений`, `СписокЗначений`), включая `DataPath` колонки, `Editor` и BSL-события ячейки колонки (`OnChange`, `StartChoice` и т.д.).
   - Полные имена событий формы, элементов и таблиц (включая `OnChange` с тегом `2147483647`).
   - Типы реквизитов формы `<Attributes><Attribute><ValueType .../>` и прямые привязки `DataPath` к реквизитам формы.

## 4. Структура будущего скилла (`skills/oneform/SKILL.md`)

1. **Когда вызывать**: любой запрос на просмотр, доработку, рефакторинг или создание с нуля обычной формы 1С, внешней обработки (`.epf`) или внешнего отчёта (`.erf`).
2. **Точечный workflow**:
   - Шаг 1: `oneform extract <path>` (только целевой объект/файл, без выгрузки всей базы).
   - Шаг 2: Чтение `Form.xml` и `Module.bsl`, внесение изменений.
   - Шаг 3: `oneform preview <path>` → проверка отсутствия случайных перекрытий и демонстрация `FormPreview.html` (или скриншота через `agent-browser`) пользователю.
   - Шаг 4: После явного подтверждения пользователем — `oneform pack <path>` для генерации `Ext/Form.bin` или `.epf`/`.erf`.
3. **Справочник разметки `Form.xml`**: краткие шаблоны всех элементов, стандартных высот (`19px` поле ввода, `24px` командная панель, `21px` кнопка) и правил привязки `DataPath` и `Events`.
