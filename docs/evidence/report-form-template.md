# report-form-template — `new-form --kind report` из формы Конфигуратора (V3)

**Дата:** 28.10.2026. **База:** «Бух.» (платформа 8.3.27.2342), пользователь `admin`; внешние отчёты и обработка собирались `erf-build` / `epf-build` и открывались запускателем `scripts/1c-e2e/live/live.py` (`ВнешнийОтчет.<путь к .erf>` / `ВнешняяОбработка.<путь к .epf>`; запускатор дополнен выводом реквизитов формы и вызовом `СформироватьНажатие`, копия — `target/night/launcher_rep.bsl`, в git не лежит).
**Изменение OpenSpec:** `report-form-template`, п. 1.1–1.3.

## Из чего состоит шаблон

`src/templates/new_form/report.form.bin` (73 842 байта, весь `Ext/Form.bin`, пустой модуль) — форма `ФормаОтчета` образца `tests/fixtures/configurator-report.erf` (`erf-dump`), из которой патчер `oneform` (`extract` → правка `Form.xml` → `pack`) убрал пользовательские `ПолеВвода1` (id 4), `Надпись1` (id 5), `Кнопка1` (id 6) с обработчиком `Кнопка1Нажатие`, реквизит `ПолеВвода1` (id 5) и текст модуля. Остались: главный реквизит `ОтчетОбъект` (id 3), расширение формы `343b4e00`, `Результат` (id 1), `ДействияФормы` (id 2), `Отбор` (id 7, 60 колонок, привязка к компоновщику настроек), размер 520 × 300. `TypeId` владельца (`8ee53033-…`) заменён заполнителем `7f5a1c00-0000-4000-8000-000000000005`, подпись — `Отчет  %ИмяОбъекта%`; `new-form` подставляет `TypeId` объекта и имя (контейнер `Form.bin` пересобирается, `rebuild_bin`). Получение: `python scripts/mine_blank_forms.py --report-dump <erf-dump образца>`. Шаблон обработки получен тем же путём без реквизита `ТаблицаНоменклатуры` (3 479 → 3 371 байт).

Поток после удаления — то, что пишет `pack` (счётчики и таблицы перечисления в корневой записи пересчитаны патчером: `{0,1,3},{0,2,3},{0,7,3}` вместо `…{0,4,3}…`). Побайтно «как записала бы платформа» не проверялось: платформа при пересохранении `.erf` меняет оформление скобок, GUID-ы экземпляров кнопок и `ZOrder` (в повторной выгрузке отличаются только две строки `ZOrder` в `Form.xml`).

## Команды

```
erf-init -Name ТестОтчет -WithSKD            # схема — Template.xml образца
oneform new-form skd/ТестОтчет --kind report --name ФормаОтчетаНовая --default
правка: Button «Сформировать» (id 8, <Click>СформироватьНажатие</Click>) + FormModule.bsl
        Процедура СформироватьНажатие(Элемент) Экспорт
          ЭлементыФормы.Результат.Область(1, 1).Текст = Строка(ТипЗнч(ОтчетОбъект)) + "|" + ОтчетОбъект.ТекстПроверки();
        и Функция ТекстПроверки() Экспорт в модуле объекта отчёта
oneform pack skd/ТестОтчет ; erf-build → skd.erf ; erf-dump → повторная выгрузка
live.py ВнешнийОтчет.<skd.erf> ФормаОтчетаНовая new out.txt out.png
```

## Решения и что НЕ доказано

* Для отчёта без схемы `new-form --kind report` **не отказывает и не предупреждает**: форма открывается и совпадает по дампу; таблица `Отбор` осмысленна только со схемой — это записано в `docs/agent-guide.md`.
* Стандартная кнопка «Сформировать» (`Standard:1`) формы не нажималась (запускатор без GUI-автоматизации): проверен вызов модуля объекта через `ОтчетОбъект` из своей кнопки, а не формирование по СКД.
* Своя кнопка нажималась вызовом процедуры (`Экспорт`) запускателем, а не щелчком мыши.
* Поведение формы без схемы в Конфигураторе (какую форму он создаёт для такого отчёта) не сверялось: третьего образца нет.
