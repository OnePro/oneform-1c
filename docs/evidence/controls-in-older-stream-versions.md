# controls-in-older-stream-versions — элементы в формах потока версий 25 и 26

**Состояние: закрыто в ночь 27–28.10.2026** (платформа 8.3.27.2342; базы: УТ 10.3.52.2 для версий 25 и 26, «Бух.» для версии 27). Не проверено: см. раздел в конце.

## Причина падения
Живая проверка показала аварийное завершение 1С (`richui.dll`) на форме УТ версии 26 при добавлении поля ввода, привязанного к **новому реквизиту формы `String`**. Поиск причины (форма `Отчеты.ABCАнализПродаж/Форма`, одна правка за раз):

| Правка | Результат |
|---|---|
| `LabelDecoration` / поле без привязки / поле к существующему реквизиту / `CheckBox` / `Button` | открывается |
| новый реквизит `Boolean` + поле или `CheckBox`; новый `String` + `CheckBox` | открывается |
| новый реквизит `String` + `InputField` | **авария** (версия 26 и версия 27: `Обработки.КурсыВалютРБК/Форма` — то же) |

То есть причина — не версия потока, а запись поля: собственный шаблон поля (`{S,100,N}`) обязан совпадать с шаблоном реквизита (в корпусе всегда равны). Исправлено в `binding_defaults.rs` (`form_attribute_type`), после исправления поле открывается и привязано (дамп [`fldnewfix`](files/controls-in-older-stream-versions/fldnewfix.txt.gz)).

Записи прототипов (донор — формы версии 27) у потока 25 / 26 короче версии 27 (у версии 27 в конце записи лишние элементы; число элементов расходится почти у всех видов). Платформа приняла прототипы версии 27 в формах 25 / 26 для четырёх видов, остальные в живой 1С не проверялись, поэтому `pack` их в потоке 25 / 26 отказывает (`check_stream_version_additions` в `form_patch.rs`).

## Проверка в живой 1С (УТ, версии 25 и 26)
Форма взята из полной выгрузки `cfg-before`, правка `Form.xml` + `FormModule.bsl`, `oneform pack`, частичная загрузка в базу, открытие лаунчером, дамп свойств. Добавлено: `LabelDecoration` с подписью, `InputField` без привязки, `CheckBox`, `Button` с `<Click>` и процедурой в модуле (стоит до тела модуля); где у формы есть `<Attributes>` — ещё реквизиты `String(50)` и `Number(10,2)` и по полю ввода к каждому.

| Версия | Форма | Добавлено | Результат (дамп) |
|---|---|---|---|
| 26 | `Отчеты.ABCАнализПродаж` / `Форма` | 4 вида + `String` + `Number` | открыта; все элементы, подписи, `Данные` = имя реквизита, `Значение` числа `0` ([v26a](files/controls-in-older-stream-versions/v26a.txt.gz)) |
| 26 | `Обработки.ДокументыЭлектронногоОбмена` / `Настройки` | то же | то же ([v26b](files/controls-in-older-stream-versions/v26b.txt.gz)) |
| 26 | `Обработки.ПредупреждениеОРазницеВоВремениССервером` / `Форма` | то же | то же ([v26c](files/controls-in-older-stream-versions/v26c.txt.gz)) |
| 25 | `Отчеты.ДвиженияДокумента` / `Форма` | то же | то же ([v25b](files/controls-in-older-stream-versions/v25b.txt.gz)) |

Отказы (без загрузки в базу): `Table` в форме версии 26 (`ABCАнализПродаж/Форма`) и версии 25 (`ДвиженияДокумента/Форма`):
`edited Form.xml of form 'Форма': line N: Table 'ТаблицаЖ' (id N): adding Table to forms of stream version 26 is not supported`, `kind: unsupported-stream-version`. Форма без `<Attributes>` (`БыстроеОсвоение/ФормаПодготовки`): отказ `form attributes: element <Attributes> added at 'Attributes' is not supported` (ограничение раздела реквизитов).

## Проверка на версии 27 («Бух.»)
Справочник `СинхронизацияПланаСчетов`, форма `ФормаЭлемента` (поток версии 27). Добавлены реквизиты формы `String(50)`, `Number(10,2)`, `Date`, ссылка `СправочникСсылка.СинхронизацияПланаСчетов` и по полю ввода к каждому: форма открыта, `Данные` у полей — имена реквизитов, `Значение` — `Строка`, `Число 0`, `Дата 01.01.0001`, `Синхронизация плана счетов` ([buh1](files/controls-in-older-stream-versions/buh1.txt.gz)). Это защищает исправление шаблона поля на версии 27.

## Прогон `pack` по корпусу УТ (формы версий 25 и 26 из области `validate`)
По одному виду на форму, шаблон: элемент в конец `ChildItems` ([свод](files/controls-in-older-stream-versions/sweep-v25-v26.jsonl.gz)); после `pack` структура потока проверена (запись элемента найдена, шаблон поля равен шаблону реквизита, связь поля с реквизитом).

| Вид | Версия 26 (778 форм) | Версия 25 (259 форм) |
|---|---|---|
| `LabelDecoration` | 775 принято, 3 отказ | 259 принято |
| `InputField` без привязки | 775 / 3 | 259 / 0 |
| `CheckBox` | 775 / 3 | 259 / 0 |
| `Button` | 775 / 3 | 259 / 0 |
| `InputField` + новый реквизит `String` | 759 принято, 13 отказ, 6 пропущено (нет `ChildItems` / `Attributes`) | 252 принято, 4 отказ, 3 пропущено |
| `Table` | 778 отказ `unsupported-stream-version` | 259 отказ `unsupported-stream-version` |

Структурных расхождений (`STRUCT`) нет. Отказы: у 3 форм — `PUBLISH_VERIFY_FAILED` («control moved to another parent or page», причина не разбиралась); 17 — раздел реквизитов не принят (`this <ValueType> is not supported`), причина не разбиралась.

## Состояние баз после проверки
* УТ: после загрузки оригиналов 10 затронутых форм полная выгрузка конфигурации побайтно равна `cfg-before` (кроме `ConfigDumpInfo.xml` — отметки версий — и одной строки `ObjectId` в `Configuration.xml`, которая меняется при каждой выгрузке).
* «Бух.»: изменялась одна форма (`Справочники.СинхронизацияПланаСчетов` / `ФормаЭлемента`), восстановлена из выгрузки до проверки, повторная выгрузка формы и объекта совпала с исходной.

## Не проверено
* Виды, кроме `LabelDecoration`, `InputField`, `CheckBox`, `Button`, в потоках 25 / 26 (`Table`, `Panel`, …) — пишутся только в версии 27, в 25 / 26 отказ.
* Версии потока 19–23: добавление не поддерживается; в живой 1С не проверялось.
* Срабатывание обработчика кнопки (нажатие): проверено, что форма с процедурой открывается, и подпись кнопки.
* Реквизиты формы `Date` / ссылка в потоках 25 / 26: проверены только `String` и `Number`.
