# Эксперимент: повышает ли `DESIGNER /ConvertFiles` версию потока формы

Дата: 2026-10-28. Платформа 8.3.27.2342, Windows, только пакетный режим (без окна Конфигуратора). Код `oneform` не менялся.
Версия потока — первое число декодированного потока формы (`Reference/FormStream.bin` после `oneform extract`).

## Подготовка

Готовых `.epf` с формами версии 25 / 26 нет (все найденные `.epf` и `.erf` — формы версии 27), поэтому образцы собраны:

1. База — копия `ut_zoo` (УТ 10.3.52.2, режим совместимости 8.2.13) в `target/night/convert/base`; исходная база не менялась.
2. `epf-dump` обработки `donor.epf` → XML; в `Forms/Форма/Ext/Form.bin` подложены формы из выгрузки УТ (`target/corpus/ut2`): версия 25 — `БыстроеОсвоение/ФормаПодготовки`, версия 26 — `ПомощникНастройкиОбменаДанными/ФормаПомощи`, версия 27 (контроль) — `РабочееМестоМенеджера/ФормаОписанияТовара`.
3. `epf-build` (`-Checks off`) → `v25.epf`, `v26.epf`, `v27.epf`. Повторное `oneform extract` показало 25 / 26 / 27: сборка из XML версию потока **сохраняет** (`Form.bin` не пересериализуется).
4. Дополнительные файлы: `РабочееМестоМенеджера.epf` (6 форм, версия 27, владелец), сторонняя `.epf` из «Загрузок» (3 формы, версия 27), два внешних отчёта `.erf` (`oneform` их не читает — сравнение только по sha256).

## Маршрут A: `/ConvertFiles`

```
1cv8.exe DESIGNER /DisableStartupDialogs /F <база> /N admin /ConvertFiles <каталог или файл> /Out <лог>
```

В git-bash нужен `MSYS2_ARG_CONV_EXCL='*'`: иначе `/F`, `/Out` превращаются в пути, команда сразу завершается кодом 1 без журнала.

| Файл | Версия до | Версия после | sha256 | Размер |
|---|---|---|---|---|
| `v25.epf` | 25 | 25 | совпал | 9432 |
| `v26.epf` | 26 | 26 | совпал | 9396 |
| `v27.epf` (контроль) | 27 | 27 | совпал | 9559 |
| `РабочееМестоМенеджера.epf` (6 форм) | 27 ×6 | не читали (sha256 совпал) | совпал | 288114 |
| сторонняя `.epf` (3 формы) | 27 ×3 | то же | совпал | 48949 |
| `ВнешнийОтчет1.erf`, `ЗадолженностьПоСрокамВозникновения.erf` | — | — | совпал | 13641, 23550 |

Каталог из 6 файлов, один файл, пустая база без конфигурации (`CREATEINFOBASE`) и база УТ — результат один: код выхода 0, журнал «Конвертация файлов успешно завершена», **содержимое файлов побайтно прежнее**; обновляется только время изменения (файл перезаписан тем же содержимым).

## Маршрут B: выгрузка и сборка (без `/ConvertFiles`)

`epf-dump` (`/DumpExternalDataProcessorOrReportToFiles`) → `epf-build` (`/LoadExternalDataProcessorOrReportFromFiles`), та же база.

| Файл | Версия до | Версия после | Что ещё изменилось |
|---|---|---|---|
| `v25.epf` | 25 | **27** | запись элемента 10 → 16 элементов, хвост `…,4,4,5}` → `…,4,4,6,750,480,96}`; в `Form.xml` появился `<LabelPictureLocation>Right</LabelPictureLocation>` |
| `v26.epf` | 26 | **27** | запись реквизита `{{0},0,1,"ОбработкаОбъект",<шаблон>}` (5 элементов) → `{{0},0,0,1,"ОбработкаОбъект",<шаблон>}` (6 элементов, лишнее `1,` — признак `with_kind` в `format_attr_record`); в `Form.xml` пропал `<StoredData>true</StoredData>` |
| `РабочееМестоМенеджера.epf` | 27 ×6 | 27 ×6 | не побайтно: у всех форм изменился поток (новые GUID, счётчик `…,184,…` → `…,185,…`), в `Form.xml` формы `ОсновнаяФорма` заголовки платформенных пунктов командной панели «Действия» → «Подменю», «Иерархический просмотр» → «Действие6» (язык `ru` → `#`), макет `ВзаиморасчетыКонтрагента` стал на 184 байта меньше |

Версия поднимается уже на **выгрузке** (`Form.bin` в выгрузке — версия 27; загрузка `Form.bin` версии 25 / 26 без выгрузки версию не меняет, см. «Подготовка», п. 3). Модули (`ObjectModule.bsl`, `FormModule.bsl`) побайтно прежние. `oneform validate` по перевыгруженным v25 / v26: `IN_SCOPE`.

## Вывод

`/ConvertFiles` на 8.3.27 **не повышает** версию потока формы и вообще ничего не меняет в файлах `.epf` / `.erf`, которые уже в формате 8.3: содержимое побайтно прежнее, обратимость и совместимость со старыми платформами не затрагиваются. Версию 25 / 26 → 27 поднимает цикл «выгрузка в XML → сборка» (маршрут B), причём ценой потерь: у форм версии 27 он тоже перестраивает поток (GUID, подписи платформенных команд, макеты), поэтому для правки форм УТ его применять нельзя — `oneform pack` сохраняет всё остальное побайтно. Версия 27 — результат пересериализации платформой 8.3.27; открывается ли такой файл платформой 8.2 / 8.3 ранних выпусков, не проверялось.

## Пределы

- Только платформа 8.3.27.2342; других платформ в системе нет, поэтому «блокирует ли конвертация старые платформы» не проверено.
- У `ConvertFiles` не было входа в формате старой платформы (файлы старше 8.3 не нашлись): возможно, команда меняет только такие файлы; для 8.3-файлов — идемпотентна.
- Образцы 25 / 26 — формы УТ, подложенные в чужую обработку (две формы, по одному образцу каждой версии); реквизит формы проверен только главный (`ОбработкаОбъект`), не пользовательские.
- Конвертированный файл в живой 1С не запускался (файлы не менялись, запуск ничего бы не добавил); перевыгруженные v25 / v26 не открывались в 1С, проверен только повторный разбор `oneform` и `validate`.
- Рабочие артефакты: `target/night/convert/` (`conv-orig/`, `conv/`, `rt/`, `rtx/`, `work/`), журнал шагов `target/night/convert-exp.md`.
