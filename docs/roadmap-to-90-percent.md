## 1. Контекст и аналитическая основа

По результатам исследования синтакс-помощника и документации (`1c-ordinary-forms-research`) в обычных формах насчитывается **62 объекта, 610 свойств и 90 событий**.

Аудит всех 1 481 форм реальной рабочей базы `dental` показал ярко выраженный **закон Парето**:
1. **99.4% всех элементов управления в продакшене (38 406 из 38 635) приходятся всего на 10 базовых типов контролов**:
   - Кнопки (`Button`) — 19 657 (88.4% форм)
   - Надписи (`LabelDecoration`) — 6 742 (63.7% форм)
   - Поля ввода (`InputField`) — 4 498 (50.0% форм)
   - Командные панели (`CommandBar`) — 2 847 (98.3% форм)
   - Табличные поля (`Table`) — 1 435 (56.3% форм)
   - Панели (`Panel`) — 736 (27.5% форм)
   - Флажки (`CheckBox`) — 709 (19.4% форм)
   - Поля выбора (`ChoiceField`) — 664 (17.2% форм)
   - Рамки групп (`UsualGroup`) — 617 (15.9% форм)
   - Табличные документы (`SpreadsheetDocumentField`) — 492 (20.9% форм)
2. **Все 10 топ-контролов уже есть в нашем доноре (`DonorFormV2`, 26 из 27 типов контролов)** и поддерживают полный цикл создания, удаления, позиционирования и настройки основных свойств.
3. Редкие контролы (`ListBox`, `TextDocumentField`, `HTMLDocumentField`, `ProgressBar`, `TrackBar`) составляют суммарно **< 0.6%** базы, а `ActiveX`, диаграммы Ганта и географические схемы составляют **0.0%**.

## 3. Четыре спринта реализации

### 🟢 Спринт 1: Ссылочные типы `ValueType` и квалификаторы (Критический P0) — ✅ ВЫПОЛНЕНО
- **Целевое покрытие:** **89.2% форм**
- **Статус OpenSpec:** Заархивирован (`openspec/changes/archive/2026-10-24-pack-ref-valuetypes-and-typelink/`)
- **Почему это важно:** В базе `dental` реквизиты (`<Attributes>`) присутствуют в **99.2% форм** (1 469 из 1 481), и большинство из них ссылаются на прикладные объекты (`СправочникСсылка.*`, `ДокументСсылка.*`).
- **Задачи:**
  1. `1.1–1.2`: Фикстуры со ссылочными реквизитами на основе дампа конфигурации (`<xr:GeneratedType>`).
  2. `2.1–2.2`: Модуль сопоставления `xr:TypeId` ↔ имя метаданных (`src/metaref.rs`); сохранение канонического `refGuid="..."` и справочного `title="..."` при `extract`.
  3. `3.1–3.2`: Патчинг ссылочных типов (одиночных и составных) при `pack` с сохранением сырых байтов неизменённых паттернов; квалификаторы `String` (`length`) и `Number` (`digits`, `fractionDigits`).
  4. `5.1–5.2`: Сквозной тест round-trip через Конфигуратор 1С (`8.3.27.2342`) и проверка `cargo test --locked`.

---

### 🟢 Спринт 2: Привязка границ (`ПривязкаГраниц` / Anchors) (Критический P0) — ✅ ВЫПОЛНЕНО
- **Целевое покрытие:** **91.5% форм** (преодоление барьера 90%)
- **Статус OpenSpec:** Заархивирован (`openspec/changes/archive/2026-10-24-pack-control-anchors/`)
- **Почему это важно:** В обычных формах при растягивании окна элементы (особенно таблицы и кнопки внизу) привязаны к краям. Без этого при изменении геометрии формы вёрстка ломается.
- **Слот в потоке:** `geom[6..9]` в 25-элементном блоке геометрии контрола.
- **Задачи:**
  1. Фиксация кодирования 4 границ (`Top=0`, `Bottom=1`, `Left=2`, `Right=3`, `None=6`) и per-edge `*Target`/`*Offset`.
  2. Поддержка в `Form.xml`: `<Anchors left="..." top="..." right="..." bottom="..."/>` (с частичным патчем только указанных рёбер и сохранением вторичной пропорциональной привязки).
  3. Патчинг `geom[6..9]` в `src/form_patch.rs` для существующих и добавляемых из донора контролов.
  4. Проверка через Конфигуратор 1С (`8.3.27.2342`).

## 4. Контрольный протокол приёмки и архитектурные правила

### Архитектурный принцип: Первичность сырых идентификаторов (GUID / ID)
**Каноническим источником истины всегда является сырой первичный идентификатор (GUID / числовой ID / код перечисления), извлечённый напрямую из бинарного потока формы.**  
Человекочитаемое имя объекта (имя метаданных, синоним) выводится как справочная аннотация (`title="..."` или текстовое содержимое тега), но **никогда не замещает и не отбрасывает первичный идентификатор**:
- **Типы значений (`ValueType`)**: `refGuid="<uuid>"` (первичный источник истины) + `title="Справочник.Контрагенты"` (справочная аннотация). При обратной сборке `refGuid` используется напрямую, а `title` служит удобным фолбэком для ручной правки человеком.
- **Привязка данных (`DataPath`)**: `attributeId="14"` (числовой ключ связи) + `<DataPath ...>ИмяРеквизита</DataPath>` (читаемое имя).
- **Колонки и кнопки**: `id="..."` (числовой идентификатор) + `name="..."` (имя элемента).
- **События**: `id="70000"` (числовой тег события платформы) + `<Event id="...">ИмяОбработчика</Event>` (имя BSL-процедуры).
- **Стили и цвета**: `ref="<guid>"` (GUID элемента стиля) + `name="..."` (имя цвета/шрифта).

### Критерии завершения каждого спринта
Каждый спринт считается завершённым только при выполнении всех 6 критериев:

1. **OpenSpec-цикл:** `propose -> validate --strict -> apply -> sync -> archive`.
2. **Оффлайн-тесты:** `cargo test --locked` проходит на 100% (без установленной 1С).
3. **Линтер:** `cargo clippy --all-targets -- -D warnings` чист.
4. **Конфигуратор 1С:** Реальный round-trip через установленную платформу:
   ```bash
   1cv8.exe DESIGNER /F "test-db" /DumpExternalDataProcessorOrReportToFiles <dump> <epf>
   1cv8.exe DESIGNER /F "test-db" /LoadExternalDataProcessorOrReportFromFiles <dump>/root.xml <out.epf>
   ```
5. **Выборочный прогон на базе `dental`:** `oneform pack` успешно отрабатывает без ошибок на выборке реальных форм.
6. **Актуализация документации:** Запуск `python scripts/build_coverage_data.py` для обновления дашборда `docs/coverage/index.html`.
