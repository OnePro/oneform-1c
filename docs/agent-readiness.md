## Что выяснено по дороге

* Новый элемент без согласованных обратных ссылок привязок ломал раскладку всей формы в 1С (форма не растягивалась) —
  это не видно ни в тестах, ни в XML; исправлено, см. `src/form_patch/anchors.rs`.
* Размер шрифта: правка размера сбрасывала курсив/подчёркивание/зачёркивание; исправлено.
* Служебные бинарные записи занимали 70 % `Form.xml`; теперь по умолчанию их нет.

## Известные ограничения

* Формы формата платформы 8.0 (≈4 % УТ 10.3): доступен только модуль.
* Формы с дублирующимися именами элементов (≈0,6 %): правка XML отклоняется.
* Командные панели: добавлять, удалять, переставлять кнопки и подменю нельзя; подписи панелей с вложенными подменю (≈15 % таких правок) не поддержаны (см. `todo.md`, A2).
* Привязка к реквизитам объекта поддержана для полей и таблиц (`Корень.Имя`, в том числе стандартные реквизиты); таблицы и колонки табличных частей: добавление таблицы, перепривязка, добавление и удаление колонок (см. `agent-guide.md`).
* Стандартный реквизит, которого у объекта нет (справочник без наименования, без родителя), отклоняется; коды `Проведен`, `ПометкаУдаления`, `Предопределенный` не поддержаны, пока нет образца.
* После обновления `oneform` ранее выгруженные формы нужно выгрузить заново (`extract`): при расхождении файлов-проекций `pack` отказывает и подсказывает это.
* Колонку «только чтение» нельзя сделать редактируемой (у неё нет встроенного редактора): отклоняется; `ReadOnly` самой таблицы меняется.
* Удаление элемента, на который привязаны другие: зависимые сохраняют положение, но растягиваются иначе.
* Конфигурационные формы (`Ext/Form.bin`) проверены тестами и фаззингом, но не в живой 1С: тестовая база даёт на открытии
  исходной формы собственную ошибку (отсутствуют реквизиты конфигурации).

## Область применимости

Состояние на 27.10.2026. `oneform validate` (изменение `add-form-scope-validator`) по каждой обычной форме решает `IN_SCOPE` / `OUT_OF_SCOPE`:
обычная форма 8.2/8.3, нет неподдерживаемых видов элементов, имена элементов уникальны, путь «без правок» воспроизводит поток, `src/` актуален
(определение и коды причин — `agent-guide.md`). Прогон: релизная сборка, `-j 3`, корпуса только на чтение (команда ничего не пишет), `src/` в корпусах выгружен прежней версией `oneform` (`Form.xml` версии 2.1).

| Корпус | Форм | В области (строгий учёт устаревшей проекции, до смены правила) | В области (текущее правило: устаревшая проекция не мешает) | `format-8.0` | `duplicate-name` | `unsupported-control` | `round-trip-differs` | `stale-projection` | Время |
|---|---|---|---|---|---|---|---|---|---|
| Бух. | 1481 | 0 (0 %) | 1477 (99,7 %) | 0 | 4 (0,3 %) | 0 | 0 | 1481 | 53 с |
| УТ 10.3 | 1525 | 0 (0 %) | 1453 (95,3 %) | 61 (4,0 %) | 11 (0,7 %) | 0 | 0 | 1464 | 94 с |

* Первоначально `stale-projection` считалась причиной выхода из области; теперь это только указание «выполните `extract`» (форма остаётся `IN_SCOPE`), поэтому правый столбец — текущая доля. `stale-projection`: `src/` корпусов выгружен до перехода `Form.xml` на версию 2.2. После повторного `oneform extract` она должна исчезнуть (на корпусах не проверялось: они только на чтение); столбец «без учёта» — доля форм, у которых нет других причин.
* `format-8.0` — только УТ: 61 форма, корень потока 19 (5), 20 (36), 23 (20); `Form.xml` у них нет, доступен модуль. Совпадает с прежней оценкой «≈4 %».
* `duplicate-name`: 4 формы Бух. и 11 формы УТ (среди них `DataProcessors/ОбновлениеКонфигурации`, `DataProcessors/ПанельФункций`, `CommonForms/НастройкаПараметровУчета`); совпадает с прежней оценкой «≈0,6 %».
* `unsupported-control` и `round-trip-differs` на корпусах не встретились: `ActiveXControl` в этих конфигурациях нет, а проход «без правок» — это путь `pack` без изменений, он проверяет согласованность проекции с потоком (идентификатор, имя, вид, родитель каждого элемента), но не пересчитывает свойства; такие отказы появляются только на искажённых потоках (см. `tests/validate.rs`).
* Контейнер формы побайтно не воспроизводится: на корпусе Бух. ни один `Form.bin` не совпал с пересобранным (в файле есть заполнение, которое `pack` не сохраняет), поэтому проверяются записи контейнера, а не его байты.
