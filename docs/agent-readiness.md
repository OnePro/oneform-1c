# Готовность oneform для ИИ-агентов: реестр «возможность → статус → как проверено → доказательство»

Состояние на 28.10.2026. Руководство для агента: [`agent-guide.md`](agent-guide.md) (стабильный режим), [`experimental-form-editing.md`](experimental-form-editing.md) (экспериментальная запись раскладки). План и долг проверки: [`todo.md`](todo.md).

> **Статус.** Стабильно: чтение (`extract`, `validate`, `lint`, `preview`, `check`, `diagnose`, `history`, `feedback`) и правка текста модулей через `pack`. Всё, что перезаписывает поток формы по `Form.xml` (свойства и элементы, панели, таблицы значений, реквизиты, `new-form`, `clone-form`), — **экспериментально**: оценки «сделано» в реестре ниже относятся к этой экспериментальной записи и **не гарантируют, что 1С откроет форму** (пилот Scany1C 28.10.2026: `Font` / `HeaderFont` и командная панель в `.epf` дали форму, которую 1С не открывает). Запись требует флага `--experimental`; без него `pack` пишет только текст модулей. Дефекты — [`experimental-form-editing.md`](experimental-form-editing.md), «Известные дефекты экспериментальной записи»; задачи — [`todo.md`](todo.md), «Находки пилота Scany1C 28.10.2026».

Продукт — патчер: правка существующих форм, новые формы через `new-form` / `clone-form` / донорские прототипы и шаблоны. Полного компилятора формы «с нуля» нет и не будет (решение владельца 28.10.2026). `preview` показывает **приблизительную** раскладку (положения, размеры, привязки), а не пиксельно точную картинку.

## Как читать «как проверено»

* **живая 1С** — есть дамп свойств или снимок экрана запущенной формы (база Бух., внешняя обработка / отчёт из XML-выгрузки).
* **пакетный Конфигуратор** — только `DumpExternalDataProcessorOrReportToFiles` / `LoadConfigFromFiles`: Конфигуратор принял файл, форму никто не открывал.
* **тесты** — офлайн-тесты `cargo test` (отражают текущий код, но не 1С; golden-эталоны переписываются флагом `GOLDEN_BLESS`, принимать их только с диффом).
* **не проверено** — доказательств нет.

Доказательства живых проверок лежат в git: сводки по областям — [`evidence/`](evidence/README.md) (дата, база, команды, результат, сырые дампы и снимки в `evidence/files/`), инструменты — [`scripts/1c-e2e/live/`](../scripts/1c-e2e/live/README.md). Если у утверждения в столбце «Доказательство» стоит «нет», артефакта на диске не нашлось. Архивные изменения OpenSpec с «проверено в 1С» без файла доказательств перечислены в [`evidence/README.md`](evidence/README.md) (`python scripts/check_evidence.py`).

## Что выяснено по дороге

* Новый элемент без согласованных обратных ссылок привязок ломал раскладку всей формы в 1С (форма не растягивалась) — это не видно ни в тестах, ни в XML; исправлено, см. `src/form_patch/anchors.rs`.
* Размер шрифта: правка размера сбрасывала курсив/подчёркивание/зачёркивание; исправлено.
* Служебные бинарные записи занимали 70 % `Form.xml`; теперь по умолчанию их нет.

## Известные ограничения

* Формы формата платформы 8.0 (≈4 % УТ 10.3): доступен только модуль; вне плана.
* Формы с дублирующимися именами элементов (≈0,3 % Бух., ≈0,7 % УТ): правка XML отклоняется; вне плана.
* `ActiveXControl`: не добавляется, форма с ним — вне области; вне плана.
* Бинарный `.erf` не читается (см. реестр).
* Командные панели: не поддержаны картинка, сочетание клавиш, пояснение и «кнопка по умолчанию» у новой кнопки; платформенные подменю (`StdSubmenu`) нельзя создавать и менять по составу (подробности — `experimental-form-editing.md`).
* Привязка к реквизитам объекта поддержана для полей и таблиц (`Корень.Имя`, в том числе стандартные реквизиты); коды `Проведен`, `ПометкаУдаления`, `Предопределенный` и поля ссылочных реквизитов (`Корень.Имя.Поле`) не поддержаны, пока нет образца. Стандартный реквизит, которого у объекта нет, отклоняется.
* После обновления `oneform` ранее выгруженные формы нужно выгрузить заново (`extract`): при расхождении файлов-проекций `pack` отказывает и подсказывает это.
* Колонку «только чтение» нельзя сделать редактируемой (у неё нет встроенного редактора): отклоняется; `ReadOnly` самой таблицы меняется.
* Удаление элемента, на который привязаны другие: зависимые сохраняют положение, но растягиваются иначе.
* Форма отчёта из `new-form --kind report` — форма Конфигуратора без пользовательских элементов (`ОтчетОбъект`, `343b4e00`, `Результат`, `ДействияФормы`, `Отбор`): открывается в 1С, вызов модуля объекта через `ОтчетОбъект` работает ([report-form-template](evidence/report-form-template.md)); нажатие стандартной «Сформировать» и форма отчёта без схемы в работе не проверялись.

## Область применимости

Состояние на 27.10.2026 (числа корпусов не пересчитывались). Формы вне области — `ActiveXControl`, формат 8.0, дубли имён — вне плана навсегда (решение владельца 28.10.2026): правка в Конфигураторе. `oneform validate` (изменение `add-form-scope-validator`) по каждой обычной форме решает `IN_SCOPE` / `OUT_OF_SCOPE`:
обычная форма 8.2/8.3, нет неподдерживаемых видов элементов, имена элементов уникальны, путь «без правок» воспроизводит поток, `src/` актуален
(определение и коды причин — `agent-guide.md`). Прогон: релизная сборка, `-j 3`, корпуса только на чтение (команда ничего не пишет), `src/` в корпусах выгружен прежней версией `oneform` (`Form.xml` версии 2.1).

|---|---|---|---|---|---|---|---|---|---|
| Бух. | 1481 | 0 (0 %) | 1477 (99,7 %) | 0 | 4 (0,3 %) | 0 | 0 | 1481 | 53 с |

* Первоначально `stale-projection` считалась причиной выхода из области; теперь это только указание «выполните `extract`» (форма остаётся `IN_SCOPE`), поэтому правый столбец — текущая доля. `stale-projection`: `src/` корпусов выгружен до перехода `Form.xml` на версию 2.2. После повторного `oneform extract` она должна исчезнуть (на корпусах не проверялось: они только на чтение); столбец «без учёта» — доля форм, у которых нет других причин.
* `format-8.0` — только УТ: 61 форма, корень потока 19 (5), 20 (36), 23 (20); `Form.xml` у них нет, доступен модуль. Совпадает с прежней оценкой «≈4 %».
* `duplicate-name`: 4 формы Бух. и 11 формы УТ (среди них `DataProcessors/ОбновлениеКонфигурации`, `DataProcessors/ПанельФункций`, `CommonForms/НастройкаПараметровУчета`); совпадает с прежней оценкой «≈0,6 %».
* `unsupported-control` и `round-trip-differs` на корпусах не встретились: `ActiveXControl` в этих конфигурациях нет, а проход «без правок» — это путь `pack` без изменений, он проверяет согласованность проекции с потоком (идентификатор, имя, вид, родитель каждого элемента), но не пересчитывает свойства; такие отказы появляются только на искажённых потоках (см. `tests/validate.rs`).
* Контейнер формы побайтно не воспроизводится: на корпусе Бух. ни один `Form.bin` не совпал с пересобранным (в файле есть заполнение, которое `pack` не сохраняет), поэтому проверяются записи контейнера, а не его байты.

## Эксперимент с цепочкой навыков cc-1c-skills

| Обычная форма у обработки и у отчёта | `oneform clone-form --experimental` (донор — маленькая форма) + `epf-build` | в проверке форма открылась, все 152 свойства элементов совпали с исходной формой |
| Пустая конфигурация и справочник | `cf-init` + `meta-compile` | загружается (`db-load-xml`, `db-update`) |
| Обычная форма нового справочника из чужой формы | `clone-form --experimental` с формой «Контрагенты» | загружается, но форма **не открывается**: модуль донора обращается к общим модулям и реквизитам УТ |
| Пустая форма нового справочника | клон «ФормаГруппы» → `extract`, удаление элементов и событий, пустой модуль → `pack --experimental` | в проверке открылась: остаётся командная панель «ОК / Записать / Закрыть» |
| Добавление элементов в эту форму | подпись и поле через `Form.xml` → `pack --experimental` | координаты, размеры и заголовок совпадают с заданными |

Вывод, который остаётся в силе: **обычную форму для нового объекта нельзя взять у чужого объекта как есть** — элементы, табличные части и модуль донора принадлежат донору. Рабочий путь — `new-form` (пустая форма из шаблона) или клон небольшой формы того же объекта с очисткой.

Ошибки `oneform`, найденные этим экспериментом, исправлены и закрыты тестами: удаление соседних элементов в начале списка («replacement ranges overlap»); удаление всех записей счётного списка оставляло `{0,}` (1С отвечала «Ошибка формата потока», теперь `pack` отвергает пустой элемент списка); пустой `<ChildItems>` считался изменением формы; добавляемый элемент с `DataPath` вида `СправочникОбъект.ИНН` молча терял привязку (теперь привязка поддержана, A1).
