### A1. Привязка к реквизитам объекта (пробел №1)

`Form.xml` по именам; **новое** поле привязать к реквизиту объекта и сменить существующую привязку нельзя

  (Код, Наименование, Родитель…), для табличных частей и колонок таблиц тоже;
- обратное разрешение «имя → uuid / код стандартного реквизита»: передать упаковщику таблицу имён из метаданных

- проверка: «найти по имени и записать» не должно подставлять первый попавшийся реквизит с таким именем из другого
  объекта; неоднозначности — отказ.

Готово, когда: новое поле, привязанное к `СправочникОбъект.ИНН` в форме нового справочника, показывает значение в 1С
(не только «форма открывается»); то же для обработки (`Объект.Реквизит`) и документа (шапка и табличная часть).
Оценка: 1–2 дня и проверка в 1С. Примечание: «привязка координат» из обсуждения понята как привязка полей формы

### A2. Командные панели: состав и вложенность
Сейчас: свойства существующих кнопок (подписи, подсказки, картинки) правятся (подпись стандартной кнопки по
`--dry-run` проходит, в 1С не проверено); **добавить, удалить, переставить** кнопки, добавить подменю нельзя
(`pack` отказывает: «button count mismatch»). Заголовки у кнопок панелей с вложенными подменю не поддержаны
(≈15 % таких правок в УТ).

Почему: кнопки лежат не отдельными элементами формы, а деревом внутри записи панели; образцов записи «кнопка» каждого
вида в донорской форме нет в виде, пригодном для клонирования.

Сделать:
- описать формат записи кнопки по донорской форме и конфигурациям (УТ 10.3, dental): виды (обработчик, стандартная
  команда, разделитель, подменю, стандартное подменю), флаги (checked, representation), картинки, связь с процедурой
  модуля, нумерация id внутри панели;
- добавление/удаление/перестановка кнопок и подменю любой глубины в `<Buttons>`; клонирование образца кнопки каждого вида
  из корпуса или донора;
- обработка связанных данных: в Form.xml `action="..."` для обработчика ссылается на процедуру модуля — проверять,
  что процедура есть (предупреждение), а не только менять запись панели;
- проверка в 1С: панель с добавленными кнопкой, подменю и разделителем показывается и вызывает процедуры; дамп свойств
  не отличается от формы, собранной в Конфигураторе.

Источники образцов: `DonorFormV2`, формы УТ 10.3 (1525), dental (1481). Оценка: 2–3 дня.

Временный порядок, пока команды нет: пользователь создаёт обычную форму в Конфигураторе и сохраняет, агент выгружает объект и

Сейчас: `clone-form` копирует форму объекта вместе с чужим содержимым; пустая форма делается вручную (клон
маленькой формы, удаление элементов, событий и кода).

Сделать:
- команда `oneform new-form` (или `init`) для: внешней обработки, внешнего отчёта, формы элемента справочника и
  документа — пустая форма (только стандартная командная панель), пустой модуль, регистрация в объекте

- шаблоны вшить из форм, созданных Конфигуратором (эталон пустой формы от пользователя надёжнее, чем клон-очистка);
- формы списка и выбора: пока клон, шаблоны позже;
- проверка в 1С: открытие, добавление элементов, сохранение и повторное открытие.

Оценка: 3–5 дней (обработка и отчёт быстрее, конфигурационные формы дольше).

## B. Ограничения редактирования

| № | Что | Сейчас | Что нужно |
|---|---|---|---|
| B1 | Колонка «только чтение» → редактируемая | отказ (у колонки нет встроенного редактора) | образец записи редактора колонки каждого вида |
| B2 | `ActiveXControl` как новый элемент | не добавляется (нет образца) | пример формы от Конфигуратора с ActiveX как эталон |
| B3 | Удаление последнего элемента на странице панели | отказ при проверке: страница пропадает из XML | показывать пустые страницы в `Form.xml` или принимать такое удаление |
| B4 | Формы формата платформы 8.0 (≈4 % УТ) | только модуль | решить, нужна ли поддержка |
| B5 | Формы с дублирующимися именами элементов (≈0,6 %) | правка XML отклоняется | уникальные имена в `Form.xml` либо правка по id |
| B6 | Удалённый элемент, к которому привязаны другие | зависимые остаются на месте, при растягивании окна ведут себя иначе | умнее выбирать новую привязку |
| B7 | Порядок элементов в `Form.xml` | новый элемент надо ставить после существующих, иначе загадочное «xml-mismatch» | порядок не должен иметь значения, либо понятное сообщение |
| B8 | `ZOrder`/`TabOrder` у нового элемента обязательны | без них отказ | значения по умолчанию |
| B9 | Свойства, которые `extract` не показывает: картинки, форматы колонок, заголовки таблиц (шрифты, цвета), часть флагов | сохраняются нетронутыми, править через XML нельзя | постепенно расшифровывать (по убыванию частоты) |
| B10 | Реквизиты формы: добавление, типы, табличные части формы | есть в тестах, в 1С не проверено | сквозная проверка (A4) |
