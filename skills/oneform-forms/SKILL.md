# oneform: обычные формы 1С через XML

Инструмент `oneform` (Rust CLI, `oneform.exe`) раскладывает форму в `Form.xml` + `FormModule.bsl` и упаковывает правки обратно,
сохраняя всё, что не менялось. Подробности: `docs/agent-guide.md` в репозитории oneform-1c; допустимые теги по типам
элементов: `docs/xml-reference.md`.

## Цикл

1. `oneform extract <каталог>` — создаёт `src/Forms/<Форма>/Form.xml`, `FormModule.bsl`, `FormPreview.html`.
2. Правка `Form.xml` / `FormModule.bsl`. Правила:
   * нет тега = «не трогать»; значение по умолчанию в файле не показывается (после упаковки тег может исчезнуть — это нормально);
   * бинарные служебные блоки (`raw`/`sig`, `*Record`) в XML не выводятся; если встретились (`extract --carriers`) — не править;
   * новый элемент: уникальное `name`, свободный `id`, `Left/Top/Width/Height`, `ZOrder` и `TabOrder` = следующие свободные, вставить в конец нужного `ChildItems`; привязки (`Anchors`) назначаются сами;
   * удалить элемент = удалить его XML целиком;
   * кнопки командной панели: в `<Buttons>` можно добавить кнопку-обработчик (`kind="Action" action="Процедура"` + `<Caption>`), стандартную команду (`action="Standard:N"`, `<Caption>` необязателен; коды — в `docs/agent-guide.md`, неизвестный код отклоняется со списком поддерживаемых), разделитель (`kind="Separator"`) и пользовательское подменю (`kind="Submenu"` с вложенным `<Buttons>`, до трёх уровней), удалить кнопку или подменю (с содержимым), поменять порядок и переносить кнопку между уровнями (элемент с прежним `id` внутрь другого `<Buttons>`); `id` новой не нужен (выдаётся сам); процедуру пишите в `FormModule.bsl`, иначе `pack` печатает `warning`; платформенные подменю (`StdSubmenu`) можно только оставить или перенести целиком;
   * привязка поля к реквизиту объекта: у добавленного или изменённого поля `<DataPath attributeId="N">Корень.Имя</DataPath>` (`N` и `Корень` — главный реквизит формы, `Имя` — реквизит или стандартный реквизит объекта: `Код`, `Наименование`, `Номер`, `Дата`); колонки таблиц и табличные части пока не поддерживаются.
   * `steps="…"` у `<DataPath>` (и `[токен]` в тексте, `ЭлементыФормы`, `<CheckBoxDataPath>`/`<PictureDataPath>` колонок; `CheckBoxDataPath` колонки таблицы с табличной частью можно перепривязать на другую Булево колонку) — полная связь из потока: не меняйте `steps` и текст связи из трёх и более шагов, пока это отказ (`editing multi-step links is not supported yet`); `Form.xml` версии 2.1 нужно получить заново через `extract`;
   * таблица, привязанная к табличной части объекта: `<Table>` с `<DataPath attributeId="N">Корень.Раздел</DataPath>` и `<Columns>` с `DataPath` `Корень.Раздел.Колонка`; в существующей таблице можно перепривязать, добавить и удалить колонки; Булево колонка привязывается через `<CheckBoxDataPath>` (с `<ReadOnly>true</ReadOnly>` и `<Visible>false</Visible>`, как её показывает `extract`), не через `DataPath` (подробнее в `docs/agent-guide.md`)
3. `oneform pack <каталог> --dry-run` — полная проверка без записи; смотри список правок и ошибки.
4. `oneform pack <каталог> --backup` — запись. `oneform check <каталог>` — проверка актуальности.
5. Для важных правок попроси открыть форму в 1С; `oneform preview` даёт офлайн-превью.

## Нужной формы нет

`oneform new-form <каталог объекта> --kind <processor|report|catalog-item|catalog-list|document> --name <Имя> [--synonym "…"] [--default]`
создаёт пустую обычную форму (стандартная командная панель, пустой модуль), регистрирует её в объекте (`ChildObjects`; с
`--default` ещё `DefaultForm` / `DefaultObjectForm` / `DefaultListForm`) и выполняет `extract`: дальше правка
`src/Forms/<Имя>/Form.xml`, `pack --dry-run`, `pack`. Объект — каталог выгрузки рядом с `<Объект>.xml`
(`Catalogs/Имя`, `Documents/Имя`, каталог `epf-dump` / `erf-dump`); `.epf` как файл не принимается. Вид формы должен подходить
объекту. Подробности и ограничения — `docs/agent-guide.md`, «Если нужной формы ещё нет». Форма, созданная пользователем в
Конфигураторе, тоже подходит.

## Копия формы

`oneform clone-form <Catalogs/Объект> --from <СуществующаяФорма> --name <Новая> [--synonym "…"]` копирует форму объекта
конфигурации (новый uuid, запись в `ChildObjects`); затем `extract` и обычная правка. Чужое содержимое придётся убирать:
для пустой формы берите `new-form`.

## Отказы

Сообщение содержит причину и элемент. Частые: формы с дублирующимися именами элементов (править только BSL), колонка «только чтение» не становится редактируемой (`<ReadOnly>false</ReadOnly>` у `<Column>`), заголовки кнопок командной панели со стандартными действиями, неизвестное или неоднозначное имя в `<DataPath>` реквизита объекта, путь из трёх частей и табличная часть, формы формата 8.0
(`layout unsupported`, только модуль). Таблица в `docs/agent-guide.md`.
