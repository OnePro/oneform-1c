# oneform: экспериментальная запись раскладки формы (Form.xml → Form.bin)

> **Экспериментально. Не начинайте с этого навыка.** Запись раскладки может завершиться успешно, а 1С форму не откроет (подтверждено на практике). Стабильные операции (чтение, `validate`, `lint`, `preview`, `check`, `diagnose`, `history`, `feedback`, правка текста модулей) — навык `oneform-forms`. Подробности и таблица известных дефектов: `docs/experimental-form-editing.md` в репозитории oneform-1c; допустимые теги по типам элементов: `docs/xml-reference.md`; числа и рецепты раскладки: навык `oneform-form-design`.

**Условие применения.** Только если пользователь **явно** попросил изменить раскладку формы и **подтвердил в текущем разговоре**, что понимает: это экспериментальная функция, она может сломать форму. Общая задача вроде «сделай форму красивее» подтверждением **не является**. Нет подтверждения — остановитесь, объясните риск простыми словами и предложите варианты: пользователь делает это в Конфигураторе, либо вы готовите описание изменения.

**Защита в программе.** `pack` без `--experimental` пишет только текст модулей; при правках, меняющих поток формы, `FormStream.bin` или шаблонах отказывает целиком до записи (`EXPERIMENTAL_REQUIRED`, код 2). `pack --dry-run` работает без флага и печатает `EXPERIMENTAL:`. `new-form` и `clone-form` требуют флага. Флаг допустим только для `pack`, `new-form`, `clone-form`; переменной окружения его включить нельзя. Это метка, а не замок: подтверждение пользователя обязательно.

**Известные дефекты** (28.10.2026, пилот Scany1C; таблица — `docs/experimental-form-editing.md`, «Известные дефекты экспериментальной записи»): правка `Font` / `HeaderFont` ломает форму (1С: «ошибка формата потока»), новая командная панель в `.epf` не открывается, колонки новой таблицы значений встают друг под другом.

## Цикл (после подтверждения)

1. Git-ветка или копия каталога: нужен откат и сравнение.
2. `oneform validate <каталог>` — `IN_SCOPE`; иначе остановитесь. `oneform extract <каталог>`.
3. Правка `src/Forms/<Форма>/Form.xml` (и при необходимости модуля) по правилам ниже.
4. `oneform pack <каталог> --dry-run` — ничего не пишет; список правок (`edit …`), строка `EXPERIMENTAL: …`, все `warning …` (ссылки в модуле на удалённый или переименованный элемент, осиротевшие обработчики, поле с типом донора, элемент за краем страницы; тексты — в `docs/experimental-form-editing.md`). Исправьте причину каждого предупреждения до записи.
5. `oneform pack <каталог> --experimental` (первый `pack` файла — с `--backup`) — запись; печатает `EXPERIMENTAL: …` и `history <id>`.
6. Откройте форму в 1С (или попросите пользователя): повторное декодирование в `pack` читает поток самим `oneform` и не доказывает, что платформа его примет. `oneform lint <каталог>` проверяет раскладку.
7. Любая проблема (отказ, неверное предупреждение, ошибка 1С): `oneform history restore <каталог> <id>` (флаг не нужен), затем `oneform diagnose` и `oneform feedback add --history <id> --1c-error "<точный текст ошибки 1С>" --note "<что делали>"`; сообщите пользователю. Не продолжайте править на сломанной записи.

## Правила правки Form.xml

* нет тега = «не трогать»; значение по умолчанию в файле не показывается (после упаковки тег может исчезнуть — это нормально);
* бинарные служебные блоки (`raw`/`sig`, `*Record`) в XML не выводятся; если встретились (`extract --carriers`) — не править;
* новый элемент: уникальное `name`, свободный `id`, `Left/Top/Width/Height`, `ZOrder` и `TabOrder` = следующие свободные, вставить в конец нужного `ChildItems`; привязки (`Anchors`) назначаются сами;
* удалить элемент = удалить его XML целиком;
* кнопки командной панели: в `<Buttons>` можно добавить кнопку-обработчик (`kind="Action" action="Процедура"` + `<Caption>`), стандартную команду (`action="Standard:N"`, `<Caption>` необязателен; коды — в `docs/experimental-form-editing.md`, неизвестный код отклоняется со списком поддерживаемых), разделитель (`kind="Separator"`) и пользовательское подменю (`kind="Submenu"` с вложенным `<Buttons>`, до трёх уровней), удалить кнопку или подменю (с содержимым), поменять порядок и переносить кнопку между уровнями (элемент с прежним `id` внутрь другого `<Buttons>`); `id` новой не нужен (выдаётся сам); процедуру пишите в `FormModule.bsl`, иначе `pack` печатает `warning`; платформенные подменю (`StdSubmenu`) можно только оставить или перенести целиком;
* новая `CommandBar` сразу с `<Buttons>` (обработчики, `Standard:N`, разделители, подменю) — одним `pack`; её `Anchors topTarget` может быть её же `id` из запроса; другой новый элемент к ней одним `pack` не привязывается; `ShowTabs` 0 → 1 у панели с наполнением даёт `warning` об элементах, которые не влезли в уменьшенные страницы (подробно — `docs/experimental-form-editing.md`);
* привязка поля к реквизиту объекта: у добавленного или изменённого поля `<DataPath attributeId="N">Корень.Имя</DataPath>` (`N` и `Корень` — главный реквизит формы: `N` берите из `<MainAttribute attributeId>` этой формы — `0` у формы из `new-form`, `1` у многих готовых, в примерах стоит 0 — подставьте своё; `Имя` — реквизит или стандартный реквизит объекта: `Код`, `Наименование`, `Номер`, `Дата`); реквизит ссылочного типа привязывается так же (`Корень.Организация`), поля внутри ссылки (`Корень.Организация.Наименование`) не поддерживаются; колонки таблицы и табличная часть — в пункте о таблице ниже. Кнопки добавленного поля ввода без тегов `<ChoiceButton>` / `<OpenButton>` берутся по типу реквизита (справочник, документ — обе; перечисление, план счетов, дата — выбор; число, строка, булево — без кнопок), явный тег главнее. Новый реквизит можно добавить в `<Объект>.xml` и сразу привязать (`pack` читает XML объекта); затем `pack` и `extract <объект> --replace-generated`.
* `steps="…"` у `<DataPath>` (и `[токен]` в тексте, `ЭлементыФормы`, `<CheckBoxDataPath>`/`<PictureDataPath>` колонок; `CheckBoxDataPath` колонки таблицы с табличной частью можно перепривязать на другую Булево колонку) — полная связь из потока: не меняйте `steps` и текст связи из трёх и более шагов, пока это отказ (`editing multi-step links is not supported yet`); `Form.xml` версии 2.1 нужно получить заново через `extract`;
* таблица, привязанная к табличной части объекта: `<Table>` с `<DataPath attributeId="N">Корень.Раздел</DataPath>` и `<Columns>` с `DataPath` `Корень.Раздел.Колонка`; в существующей таблице можно перепривязать, добавить и удалить колонки; Булево колонка привязывается через `<CheckBoxDataPath>` (с `<ReadOnly>true</ReadOnly>` и `<Visible>false</Visible>`, как её показывает `extract`), не через `DataPath` (подробнее в `docs/experimental-form-editing.md`)
* реквизит формы: в `<Attributes>` добавьте `<Attribute id="N" name="Имя"><ValueType kind="String|Number|Date|DateTime|Boolean|Ref|ValueTable" …/></Attribute>` (`String` с `length`, `Number` с `digits`/`fractionDigits`, ссылка с `refGuid`; `composite` писать не нужно, нет — `false`; пример: `<Attribute id="200" name="Примечание"><ValueType kind="String" length="100"/></Attribute>`) — реквизит добавляется сам по себе, привязка не нужна; `id` — свободный номер среди реквизитов (отдельно от элементов), `<Main>` не пишите; удалить = убрать `<Attribute>`, пока элемент привязан к реквизиту — отказ с именем элемента (`form attributes: … cannot be removed`); переименование и смена типа реквизита, к которому привязан элемент, фиксированная строка, колонки внутри `<Attribute>` не поддерживаются (отказ `form attributes: …`); запись реквизита `pack` подбирает по версии потока формы (формы УТ 10.3 — 19…27, Бух. — 27) и проверяет раздел реквизитов после правки;
* таблица значений: `<Table>` с `<DataPath attributeId="N">Имя</DataPath>` (реквизит `ValueTable`, новый или существующий) и `<Columns>`: `<Column name id>` с `<Header>`, `<Width>`, `<ValueType kind="String|Number|Date|DateTime|Boolean" …/>` (нет — `String`), `<ReadOnly>`, `<Editor>InputField</Editor>`, необязательным `<DataPath attributeId="N">Имя.Поле</DataPath>` (нет — поле называется как колонка); отказ: тип `Time`/ссылка/составной, `Events`, `FooterText`, `Tooltip`, другой редактор, `Columns` у таблицы без привязки к табличной части или `ValueTable`; колонки существующей таблицы значений не меняются; Булево колонка пишется как поле ввода, как у большинства колонок Бух., в 1С не проверялось;
* версия потока формы (первое число `FormStream.bin`): в формах версии 25 и 26 (большинство форм УТ) добавляются только `LabelDecoration`, `InputField`, `CheckBox`, `Button` (проверено в живой 1С, в том числе поле с новым реквизитом формы `String` / `Number`); `Table`, `Panel` и прочие виды — отказ `unsupported-stream-version`, форма не тронута; форма без `<Attributes>` новых реквизитов не принимает. При отказе `unsupported-stream-version` не ищи конвертацию на стороне: прочитай в `docs/agent-guide.md` раздел «Форма старой версии потока (25 / 26): что сказать пользователю» (что сказать, варианты A/B/C, риски, команды) и предложи пользователю варианты; конвертировать только с его согласия. В формах версии 27 (Бух.) — все виды. Таблица — в `docs/experimental-form-editing.md`, «Версия потока формы и добавляемые элементы»;
* примеры и рецепты (`docs/experimental-form-editing.md`, «Добавляемые элементы»): новый элемент — в конец `ChildItems`, `CheckBox` привязывается обычным `<DataPath>` (`<CheckBoxDataPath>` — только колонка таблицы), `Button` — `<Click id="0">Процедура</Click>`; минимальный XML для `LabelDecoration`, `InputField`, `CheckBox`, `Button`, `Table` — там же;
* `Anchors`: `top`/`bottom`/`left`/`right` = `Left|Right|Top|Bottom|None`, `<край>Target` (нет — форма), `<край>Offset`, вторая привязка `<край>Alt…`; нет тега — автопривязка (верх под соседом выше, левый за соседом слева, низ и правый край — размер элемента; соседи — только уже существующие элементы, по их положению в правленом `Form.xml`). Поле растягивается вместе с окном: `<Anchors right="Right" rightOffset="-30"/>`, где смещение = `Left + Width − Width формы`; надпись не растягивается — `Anchors` не писать;
* размер формы (`Width`/`Height` корня) меняется, но панели и элементы не пересчитываются: у `new-form` `ДействияФормы` и `ОсновныеДействияФормы` (`Top` = `Height` − 25) шириной в форму правьте сами (пустая `document` 346×262, `catalog-item` 400×85, `catalog-list` 400×300);
* `ValueType` нового поля ввода, привязанного к реквизиту объекта или к простому реквизиту формы, берётся из типа реквизита (строка с длиной, число, `Date`/`DateTime`, `Boolean`, ссылка; `Код`/`Наименование` справочника, `Номер`/`Дата` документа); явный `<ValueType …/>` главнее; составной или неизвестный тип остаётся донорским (`kind="ValueList"`);
* `Panel` со страницами добавляется целиком: `<Panel>` с `<ShowTabs code="1"/>` (закладки сверху; `0` — без закладок; другие коды отказ), `<Page name><Title>` на каждую страницу и элементы внутри; геометрию страниц не пишите (выводится из размера панели); `ZOrder` (0…k-1) и `TabOrder` (1…k) считаются на каждой странице отдельно; привязки — к панели (цель 0) и к элементам той же страницы. страницы существующей панели можно переименовать, добавить, удалить (вместе с их элементами) и переставить (`<Page>` по `name`; размер панели и состав страниц — разными `pack`; элементы добавленной страницы — следующим `pack`); `ShowTabs` существующей панели меняется только `0` ↔ `1` (область страниц пересчитывается сама), другие коды и `ShowTabs` вместе с правкой страниц в одном `pack` — отказ `unsupported-panel`;
* подводные камни: **сначала найдите существующий тег** (`extract` показывает `ReadOnly`, `Visible`, `Anchors`…), не вставляйте второй — отказ `duplicate <…> element`; подписи двуязычные (`ru` + `ro`): правка `ru` оставляет `ro`, новому элементу достаточно `ru`; смена `Width` поля, правый край которого привязан к другому элементу (`rightTarget`), на экране ничего не меняет — правьте и привязку; имя новой или переименованной страницы — идентификатор (иначе отказ `page-name`);
* коды отказов: `FORM_EDIT_REJECTED` — недопустимая правка (xml, дубль, реквизиты, страница, порядок в модуле; файлы не тронуты); `GENERATED_FILE_MODIFIED` — только когда изменён сгенерированный файл (`extract` поверх правленого `src/`);

## Нужной формы нет: `new-form`

`oneform new-form <каталог объекта> --kind <processor|report|catalog-item|catalog-list|document> --name <Имя> [--synonym "…"] [--default] --experimental`
создаёт пустую обычную форму (стандартная командная панель, пустой модуль), регистрирует её в объекте (`ChildObjects`; с
`--default` ещё `DefaultForm` / `DefaultObjectForm` / `DefaultListForm`) и выполняет `extract`: дальше правка
`src/Forms/<Имя>/Form.xml`, `pack --dry-run`, `pack --experimental`. Объект — каталог выгрузки рядом с `<Объект>.xml`
(`Catalogs/Имя`, `Documents/Имя`, каталог `epf-dump` / `erf-dump`); `.epf` как файл не принимается. Вид формы должен подходить
объекту. Подробности и ограничения — `docs/experimental-form-editing.md`, «Если нужной формы ещё нет». Форма, созданная пользователем в
Конфигураторе, тоже подходит.

## Копия формы: `clone-form`

`oneform clone-form <Catalogs/Объект> --from <СуществующаяФорма> --name <Новая> [--synonym "…"] --experimental` копирует форму объекта
конфигурации (новый uuid, запись в `ChildObjects`; `.` — каталог объекта, в котором вы стоите); затем `extract` и обычная правка. Работает с каталогом объекта в XML-выгрузке, для `.epf` сначала `epf-dump`. **Свои правки сначала упакуйте** (`pack`): иначе после клона `pack` даёт `SOURCE_CHANGED`, `extract` — `GENERATED_FILE_MODIFIED`, а `--replace-generated` затирает правку; `clone-form` при непринятых правках в `src/` отказывает сам. Чужое содержимое придётся убирать:
для пустой формы берите `new-form`.

`new-form --kind report` повторяет форму Конфигуратора (главный реквизит `ОтчетОбъект`, `Результат`, `ДействияФормы`, таблица настроек `Отбор`, 520 × 300); код с `ОтчетОбъект` работает (проверено в 1С). Таблица `Отбор` связана с компоновщиком настроек и осмысленна только у отчёта со схемой компоновки данных.

## Отказы

Сообщение содержит причину и элемент; файлы не тронуты. Частые: формы с дублирующимися именами элементов (править только BSL), колонка «только чтение» не становится редактируемой (`<ReadOnly>false</ReadOnly>` у `<Column>`), заголовки кнопок командной панели со стандартными действиями, неизвестное или неоднозначное имя в `<DataPath>` реквизита объекта, путь из трёх частей и табличная часть, формы формата 8.0 (`layout unsupported`, только модуль). Таблица — в `docs/experimental-form-editing.md`, «Отказы записи Form.xml и что делать»; `EXPERIMENTAL_REQUIRED` — в `docs/agent-guide.md`, «Экспериментальный режим».
