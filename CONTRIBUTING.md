# Как вносить изменения

## Запись в CHANGELOG.md

Каждое изменение, заметное пользователю `oneform` или агенту (команда, флаг, сообщение об ошибке, формат файлов, документ или навык для агента, архив релиза, поведение на какой-либо ОС), получает одну строку `- ` в разделе `## [Unreleased]` файла [`CHANGELOG.md`](CHANGELOG.md) **в том же коммите**, что и изменение. Внутренние правки без видимого эффекта (рефакторинг, тесты) записи не требуют.

* Подраздел выбирайте из фиксированного набора: `### Добавлено`, `### Изменено`, `### Исправлено`, `### Удалено`, `### Безопасность`, `### Экспериментальное`. Других названий скрипт не принимает; пустой заголовок подраздела тоже.
* Пункт — одна строка на языке пользователя: что стало иначе, без хешей коммитов.
* **Стабильное и экспериментальное.** Всё, что касается записи раскладки формы (`pack` потока формы, `new-form`, `clone-form`, `--experimental`, дефекты такой записи), идёт в `### Экспериментальное`; чтение, `lint`, `validate`, `preview`, `check`, `history`, `diagnose`, `feedback` и правка текста модулей — в остальные подразделы. Так читатель сразу видит, что изменилось в стабильном режиме, а что в том, который может сломать форму.
* Формат проверяет `python3 scripts/check_changelog.py check` (`just changelog-check`); CI запускает его на каждый push и pull request.

## Выпуск релиза

Релиз без записи в `CHANGELOG.md` невозможен: это проверяет скрипт, а не договорённость. Подробности и список проверок — [`README.md`](README.md), «Выпуск релиза».

1. Убедитесь, что в `[Unreleased]` есть пункты обо всём, что вошло в релиз.
2. Из ветки `main` с чистым деревом: `just release-dry minor` (покажет версию и перенос записей), затем `just release patch|minor|major|X.Y.Z`.
3. Скрипт `scripts/release.py` сам переносит `[Unreleased]` в раздел `[X.Y.Z] - дата`, поднимает версию в `Cargo.toml` и `Cargo.lock`, делает один коммит `release X.Y.Z`, ставит тег и отправляет его; описание релиза GitHub берётся из `CHANGELOG.md`.

Пустой `[Unreleased]` — отказ: «в [Unreleased] нет записей: описывать нечего, релиз запрещён».

## Окончания строк и переносимость

* Все текстовые файлы — LF на любой ОС: это задаёт [`.gitattributes`](.gitattributes), `core.autocrlf` настраивать не нужно. Скрипты пишут файлы с LF (`newline="\n"`).
* `python3 scripts/check_repo_portable.py` проверяет имена файлов (зарезервированные имена Windows, длину пути, регистр, NFC); его запускает CI.
* Скрипты на Python — только стандартная библиотека, shebang `#!/usr/bin/env python3`; на Windows запускайте как `python`.
* Ссылки и таблицы в Markdown: `python3 scripts/check_md_links.py` и `python3 scripts/check_md_tables.py README.md CONTRIBUTING.md CHANGELOG.md`.

## Тесты

* Rust: `cargo test --locked` и `cargo clippy --locked --all-targets -- -D warnings` (`just test`, `just clippy`).
* Скрипт `CHANGELOG.md`: `python3 -m unittest discover -s scripts/tests -v` (`just changelog-check`).
* Golden-эталоны меняются только осознанно (`GOLDEN_BLESS=1`), с диффом в коммите. Бэклог — [`docs/todo.md`](docs/todo.md).
