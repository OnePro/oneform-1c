# Живая проверка в 1С (live-check)

> **Только Windows (нужна платформа 1С):** сценарии запускают `1cv8.exe`, `powershell.exe`/`schtasks`, интерактивный сеанс.

Инструменты, которыми `oneform` проверялся в запущенной 1С: форма открывается, из неё снимается дамп свойств
каждого элемента (и при необходимости снимок экрана), дамп сравнивается с исходным. Результаты проверок — в
[`docs/evidence/`](../../../docs/evidence/README.md). Раньше эти файлы лежали только в `target/` (не в git).

## Что нужно

* Windows, интерактивный сеанс (1С запускается через планировщик задач `schtasks` на рабочем столе пользователя), 1С:Предприятие 8.3.27.
* Тестовая файловая база **«Бух.»** (копия конфигурации бухгалтерии), пользователь `admin` без пароля.
* Python 3, PowerShell, `oneform` (`cargo build --release`), навыки cc-1c-skills (`db-load-xml`, `epf-*`/`erf-*`) в `~/.agents/skills`.
* Переменные окружения:

| Переменная | Значение |
|---|---|
| `ONEFORM_BUH_DB` | **обязательна**: каталог тестовой файловой базы «Бух.» |
| `ONEFORM_1CV8` | `1cv8.exe` (по умолчанию `C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe`) |
| `ONEFORM_1CV8_BIN` | каталог с `1cv8.exe` для `load.sh` (по умолчанию `C:\Program Files\1cv8\8.3.27.2342\bin`) |
| `ONEFORM_SKILLS` | каталог навыков (по умолчанию `~/.agents/skills`) |
| `ONEFORM_LIVE_WORK` | рабочий каталог для собранных обработок и временных `.cmd`/`.vbs` (по умолчанию `target/1c-live`, не в git) |

Правила запуска (нарушение даёт «база занята» и зависшие прогоны):

1. **Один экземпляр 1С за раз.** Перед каждым прогоном завершайте `1cv8.exe` (`taskkill /F /IM 1cv8.exe`); скрипты делают это сами до и после.
2. Файл-список для частичной загрузки — UTF-8 **с BOM**, по одному объекту в строке (`Catalogs/Имя.xml`, `Catalogs/Имя/Forms/Форма.xml`, `.../Ext/Form.bin`).
3. Сообщения «константы валюты не заполнены» при загрузке игнорируются.

## Состав каталога

| Файл | Назначение |
|---|---|
| `onec.py` | общие функции: пути из переменных окружения, запуск 1С в интерактивном сеансе через задачу планировщика, снимок экрана |
| `build_launcher.py` | собирает обработку-«запускатор»: `dump-base.epf` с подменённым модулем (`launcher_module.bsl` → `a1-launcher.epf`; `std_codes_module.bsl` → `std-codes.epf`); результат побайтно совпал с ранее применявшимся |
| `epf_pack.py`, `dump-base.epf` | чтение/запись контейнера и заготовка обработки для `build_launcher.py` |
| `launcher_module.bsl` | модуль запускатора A1: открывает форму объекта конфигурации (`first` — первый существующий, `new` — новый) и пишет по каждому элементу `pre:<элемент>.<свойство>=<Тип>|<значение>` (в том числе `Данные` — привязку и `Значение` — что показывает поле), в конце `## READY` |
| `live.py` | один прогон: запускает 1С, ждёт `## READY`, при желании снимает экран (задача `oneform-shot`), завершает 1С |
| `scr.ps1` | снимок всего рабочего стола в PNG (сворачивает другие окна, разворачивает 1С) |
| `ev.ps1` | последние сообщения журнала Windows о `1cv8` — если 1С упала без вывода |
| `std_codes_module.bsl`, `run_batch.py` | пакетный запускатор: список форм → `Данные` каждого элемента и колонки таблицы в одном файле (сверка кодов привязки с рантаймом) |
| `load.sh` | частичная загрузка XML-выгрузки в базу (`db-load-xml`, режим `Partial`, `UpdateDBCfg`) |
| `cmp.py` | сравнение двух дампов: пропажи, изменённые значения, лишние свойства у прежних элементов |
| `edit_cat.py`, `mk_epf2.py` | образцы правок `Form.xml` (поля с привязкой к справочнику; таблица с колонками табличной части) |
| `links.py`, `brace.py` | печать связей (`Связи`) из `Form.bin` для сверки с `steps=` в `Form.xml` |
| `../epf_dump.py`, `../dump_diff.py`, `../e2e_*.py|sh` | дамп **внешней обработки** (запускатор `target/dump-ws/dump.epf`, отдельная база `target/db-real`) и сравнение; свойства — `e2e_sweep.py` |

Созданные на ходу `run-a1.cmd`, `run-a1shot.cmd` и `*.vbs` лежат в `ONEFORM_LIVE_WORK`. Пример `run-a1.cmd`:

```
@echo off
chcp 65001 >nul
"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" ENTERPRISE /F "<база Бух.>" /N admin /P "" /RunModeOrdinaryApplication /DisableUnsafeActionProtection /Execute "<work>\a1-launcher.epf" /C"Справочники.Имя|<work>\out.txt|ФормаАгентаН|first|" /DisableStartupDialogs /DisableStartupMessages
```

`run-a1.vbs` (`CreateObject("WScript.Shell").Run """…\run-a1.cmd""", 0, True`) запускает `.cmd` скрытым окном; задача планировщика `oneform-a1` стартует его
в сеансе пользователя (`/ru <пользователь> /it`). Снимок: задача `oneform-shot` → `powershell … scr.ps1 <png>`.

## Процедура

Объект конфигурации (справочник, документ):

1. **Выгрузка** XML конфигурации (Конфигуратор или навык `db-dump-xml`) в каталог `<cfg>`; форма — `Catalogs/Имя/Forms/Форма/Ext/Form.bin`.
2. **Извлечение**: `oneform extract <каталог с объектом>` → `src/Forms/<Форма>/Form.xml` (+ `Module.bsl`).
3. **Правка** `Form.xml` (вручную, скриптом вроде `edit_cat.py` / `mk_epf2.py`, или командами `new-form` / `clone-form`).
4. **Упаковка**: `oneform pack <каталог>` (отказ — исправить правку, не обходить).
5. **Частичная загрузка** в тестовую базу: список (UTF-8 с BOM) из файлов объекта и формы, затем
   `./load.sh <cfg> list-x.txt out/load-x` (в логе — «загрузка завершена»; иначе дамп не нужен).
6. **Дамп**: `python live.py Справочники.Имя ФормаАгентаН first out/x-after.txt out/x-after.png`
   (`new` — новый объект; для документа — `Документы.Имя`). Последний аргумент `Реквизит=s:значение;…` заполняет реквизиты объекта перед открытием.
7. **Сравнение**: сначала дамп до правки (тем же `live.py`, `out/x-before.txt`), затем
   `python cmp.py out/x-before.txt out/x-after.txt НовыйЭлемент1,НовыйЭлемент2 pre`. Допустимы только отличия у новых элементов и у тех, что правились.
8. **Вывод**: смотреть `Данные` (путь привязки), `Значение`, положение, `Видимость`; снимок — для раскладки. Выводы и ссылки на файлы — в `docs/evidence/<изменение>.md`.

Внешняя обработка / внешний отчёт (XML-выгрузка `epf-dump` / `erf-dump`): `oneform extract` → правка → `oneform pack` (обновляет `.epf` / `.erf`) →
`python ../epf_dump.py <файл> <метка> [Форма]` (дамп в `target/dumps/<метка>.txt`) → `python ../dump_diff.py <до> <после> post`.

## Как добавить сценарий

1. Выберите объект и форму в тестовой базе; снимите дамп **до** (`live.py … out/<имя>-before.txt`).
2. Напишите скрипт правки `Form.xml` (по образцу `edit_cat.py`: вставка блока перед `</ChildItems>`, свободные `id` и `ZOrder`/`TabOrder`).
3. Список для загрузки — объект, его `Forms/<Форма>.xml` и `Forms/<Форма>/Ext/Form.bin` (BOM!).
4. `extract` → правка → `pack` → `load.sh` → `live.py … <имя>-after.txt <имя>-after.png` → `cmp.py`.
5. Если нужны новые свойства в дампе — добавьте их имена в списки `Разд("…", ",")` в `launcher_module.bsl`, затем `python build_launcher.py` (пересборка `a1-launcher.epf`).
6. Положите итоговые `.txt` / сжатые `.png` в `docs/evidence/files/<область>/`, опишите в `docs/evidence/<область>.md` (дата, база, команды, что проверено, результат) и добавьте строку в «Доказательство» таблицы `docs/agent-readiness.md`.
