# oneform-1c (`oneform`)

Нативный однофайловый кроссплатформенный CLI-инструмент на Rust для распаковки, инспектирования, приблизительного HTML-превью, правки и обратной упаковки обычных форм 1С:Предприятие 8.2 / 8.3 (`Ext/Form.bin`, внешние обработки `.epf` и XML-выгрузки конфигураций и внешних обработок / отчётов). Бинарный `.erf` `extract` пока не находит (ищутся только `*.epf`): внешний отчёт поддерживается через XML-выгрузку платформы (`erf-dump`) — до появления поддержки `.erf`.

Не требует установленной платформы 1С, Python или внешних библиотек — все ассеты рендерера форм (`assets/form_render.js`, `assets/form_theme.css`, `assets/hljs_1c_xml.js`) вшиты в бинарник на этапе компиляции.

## Возможности

- **Распаковка (`oneform extract`)**:
  - рекурсивно обходит указанный каталог (параллельно через `rayon`, `-j N`);
  - распаковывает внешние обработки (`.epf`) и бинарные формы выгрузки конфигурации, внешней обработки или внешнего отчёта (`Forms/<Форма>/Ext/Form.bin`, `CommonForms/<Форма>/Ext/Form.bin`) в детерминированное дерево `src/`; бинарные `.erf` не читаются (сначала `erf-dump`);
  - извлекает модули (`ObjectModule.bsl`, `FormModule.bsl`) с сохранением исходной кодировки и переводов строк в `ExtractionManifest.json`;
  - декодирует бинарный поток обычной формы (`FormStream.bin`) в структурированный `Form.xml` (`ordinaryFormVersion="2.2"`):
    - все 27 типов элементов управления палитры обычных форм 1С 8.2;
    - многостраничные панели (`Panel` / `Page`), включая вкладки верхнего уровня самой формы и панели без корешков (`ShowTabs=0`);
    - командные панели (`CommandBar`) с индивидуальными кнопками, автозаполнением, рекурсивными подменю (`Submenu`), стандартными командами, подсказками и BSL-обработчиками;
    - табличные поля (`Table`) всех 4 классов колонок (табличные части, динамические списки, `ТаблицаЗначений`/`ДеревоЗначений`, `СписокЗначений`), включая встроенные в поток `Base64` редакторы ячеек и их BSL-события;
    - реквизиты формы (`<Attributes>`) с типами (`<ValueType>`), привязки `<DataPath>`, списки выбора (`<ChoiceList>`), события формы и элементов.
- **Офлайн HTML-превью (приблизительное) и Инспектор элементов (`FormPreview.html` и `.oneform/index.html`)**:
  - приблизительная раскладка обычных форм в стиле Конфигуратора 1С 8.2: положения, размеры, привязки (не пиксельно точная картинка; точный вид даёт только 1С); работает офлайн через `file://`;
  - интерактивный Инспектор элементов: выбор любых элементов, отдельных кнопок `CommandBar`, подменю, колонок `<Column>`, строки табличной части `<Row>`, реквизитов `<Attribute>` и самой формы `<Form>`;
  - переключение вкладок и слоёв (`Слои/Панели`, `Перекрытия`, `Скрытые`), управление видимостью (`👁`, клавиша `H`, `Alt+Клик`, контекстное меню выбора под курсором);
  - переход в один клик от события элемента/кнопки/колонки/строки к `Процедуре` в модуле формы с офлайн-подсветкой синтаксиса 1C (BSL) и XML.
- **Обратная упаковка (`oneform pack`)**: `oneform` — патчер, а не компилятор формы: он правит существующий поток формы точечно и создаёт новые формы только из вшитых шаблонов и донорских прототипов (полного компилятора «с нуля» нет и не планируется).
  - упаковывает изменённые `FormModule.bsl`, `ObjectModule.bsl`, `Reference/FormStream.bin`, `Template.html` / `Template.bin` обратно в `Ext/Form.bin` и `.epf` с проверкой целостности манифеста и атомарной транзакционной записью;
  - переносит правки существующих элементов из `Form.xml` в исходный поток формы: подписи, положение, размеры, видимость, порядок, привязки краёв (`Anchors`), цвета, шрифты, события, переименование, привязки `DataPath` и сотни других свойств каталога (список тегов по типам элементов — `docs/xml-reference.md`); также размер формы, колонки таблиц, кнопки командных панелей и страницы панелей;
  - **добавляет новые элементы** из вшитого донорского прототипа (26 из 27 типов; `ActiveXControl` не добавляется) с автоназначением `id`, автопривязками и применением имени, заголовка, геометрии, порядка и событий из XML; добавляет панели со страницами, таблицы с колонками, реквизиты формы простых типов и таблицы значений;
  - **привязывает** поля и таблицы к реквизитам объекта и табличным частям (`Корень.Имя`);
  - **удаляет элементы** вместе с поддеревом, счётчиком списка родителя и ссылками на их id;
  - отклоняет то, что не умеет, с явной ошибкой (`GENERATED_FILE_MODIFIED` и коды `unsupported-*`), не перезаписывая исходники или контейнер: перенос элемента между родителями и страницами, смену типа элемента и прочее, чего нет в `docs/agent-guide.md`;
  - сохраняет байты вне разрешённых диапазонов в **несжатом** `FormStream.bin`; контейнер и Deflate-поток могут быть сериализованы заново, поэтому гарантия не означает побайтовую неизменность всего `.epf`;
  - что проверено в живой 1С, а что только тестами, — в реестре [`docs/agent-readiness.md`](docs/agent-readiness.md).
- **Проверка актуальности (`oneform check`)**:
  - проверяет соответствие дерева `src/` исходным `.epf` и `Ext/Form.bin` (код возврата `0` — актуально, `3` — есть расхождения) для использования в CI и pre-commit хуках.
- **Низкоуровневая инспекция (`oneform props`)**:
  - дамп и побайтовый diff дерева свойств (`info` / `geom`) элементов `FormStream.bin` / `Form.bin`.

## Сборка и запуск

```bash
# Сборка релизного бинарника (target/release/oneform или target/release/oneform.exe)
cargo build --release --locked

# Запуск всех модульных, фикстурных и golden-тестов
cargo test --locked
```

### Основные команды CLI

```bash
# Извлечь все формы и обработки в каталоге (по умолчанию: текущий каталог) и построить .oneform/index.html
oneform extract <PATH>

# Проверить, соответствует ли src/ бинарным исходникам (exit 3 при расхождении)
oneform check <PATH>

# Упаковать изменения из src/ обратно в Ext/Form.bin и .epf (--backup сохраняет .bak)
oneform pack <PATH> [--backup] [--dry-run]

# Пересобрать только FormPreview.html и .oneform/index.html (приблизительная раскладка)
oneform preview <PATH>

# Проверить раскладку Form.xml (error: за краем формы, дубли; warning: пересечения, нет растягивания, нижняя панель; info: отклонения от обычного вида формы; exit 1 при error, 3 с --strict при warning)
oneform lint <PATH> [--json] [--strict]

# Решить по каждой форме, можно ли её править через oneform: IN_SCOPE / OUT_OF_SCOPE с кодами причин (ничего не пишет; exit 1, если есть форма вне области)
oneform validate <PATH> [--json]

# Новая пустая обычная форма объекта (каталог объекта выгрузки), регистрация в объекте и extract
oneform new-form <каталог объекта> --kind processor|report|catalog-item|catalog-list|document --name <Имя> [--synonym <текст>] [--default]

# Копия существующей формы объекта конфигурации
oneform clone-form <каталог объекта> --from <Форма> --name <Имя> [--synonym <текст>]

# Инспекция и сравнение низкоуровневых свойств элементов FormStream.bin / Form.bin
oneform props <FormStream.bin|Form.bin> [--control <Имя>] [--diff <Other.bin>]

# Исследование неизвестных свойств: точечная мутация одного слота потока
oneform explore mutate --spec <exp.json> --stream <FormStream.bin> --out <dir>

# Кандидатные флаговые слоты (bare 0/1) контрола для построения матрицы экспериментов
oneform explore candidates --stream <FormStream.bin> --control <Имя>

# Конвейер экспериментов: baseline + Designer gate (нужна установленная платформа 1С и база-копия)
oneform explore run --matrix <spec.json|dir> --epf <donor.epf> --base <infobase> --platform <bin-1cv8> [--corpus <dir>]
```

### Конвейер исследования свойств (`explore`)

Эксперимент — JSON-спецификация точечной мутации (`id`, `control`, `slot` вида `info[2][0][3]`, `newValue {kind: bare|quoted, value}`, `hypothesis`). `explore run` прогоняет baseline (два прогона немутированного донора; строки, нестабильные между прогонами, помечаются volatile и исключаются из чистого diff, UUID маскируются), затем каждый эксперимент: мутация одного leaf-слота с сохранением всех остальных байтов, валидация платформой (`/DumpExternalDataProcessorOrReportToFiles` + `/LoadExternalDataProcessorOrReportFromFiles` против временной копии базы), проверка выживания контрола (`accept` / `reject` / `silent-drop`) и запись фикстуры в корпус (`tests/explore/<id>/`: `original.bin`, `mutated.bin`, `normalized.bin`, `observed.json`, `net-diff.json`, `decoded-diff.json`, `manifest.json` со `schema: 1`).

Корпус воспроизводится тестом `tests/explore_corpus.rs` **без платформы** (мутация пересчитывается из manifest и сравнивается побайтово); регенерация через платформу — только явным opt-in (`ONEFORM_EXPLORE=1`, `ONEFORM_EXPLORE_BASE`, `ONEFORM_EXPLORE_PLATFORM`). Известные находки по слотам свойств: `docs/property-exploration.md`.

### Для ИИ-агентов

`oneform` рассчитан на работу агента без Конфигуратора: `extract` → правка `Form.xml`/`FormModule.bsl` → `pack --dry-run` → `pack`. Правила чтения XML, поддерживаемые операции (свойства, добавление и удаление элементов, привязки), типичные отказы и проверка в 1С описаны в [`docs/agent-guide.md`](docs/agent-guide.md); допустимые теги по типам элементов — в [`docs/xml-reference.md`](docs/xml-reference.md); навык для агента — [`skills/oneform-forms/SKILL.md`](skills/oneform-forms/SKILL.md); оформление форм по видам и проверка раскладки `oneform lint` — [`skills/oneform-form-design/SKILL.md`](skills/oneform-form-design/SKILL.md). Бинарные служебные записи в `Form.xml` по умолчанию не выводятся (`extract --carriers` возвращает их).

### Цикл редактирования формы через XML

```bash
oneform extract <PATH>
# 1. Измените Form.xml и при необходимости FormModule.bsl / ObjectModule.bsl.
# 2. Посмотрите приблизительную раскладку (положения, размеры, привязки):
oneform preview <PATH>
# 3. Откройте FormPreview.html, затем после согласования:
oneform pack <PATH> --backup
# 4. При необходимости проверьте повторным извлечением в отдельный каталог.
```

`pack` перед публикацией повторно декодирует форму и проверяет соответствие запрошенному XML, а также сохранность несжатого потока вне разрешённых диапазонов. Одновременное независимое редактирование `Form.xml` и `Reference/FormStream.bin` отклоняется как неоднозначное. Форматирование XML без семантических изменений не изменяет форму. Изменения, которых `pack` не умеет (например, перенос элемента между страницами, смена типа элемента, правка свойств, которых нет в `docs/xml-reference.md`), вызывают явную ошибку. Новые элементы клонируются из вшитого донора (Designer-эталон): события донора при клонировании сбрасываются, события нового элемента берутся из XML.

## Структура репозитория

- `src/` — исходный код CLI и библиотеки `oneform` на Rust (парсер контейнеров 1С v8, декодер `FormStream.bin`, генератор `Form.xml`, рендерер превью, упаковщик, транзакционный движок).
- `assets/` — встраиваемые в бинарник офлайн-ассеты рендерера форм и инспектора (`form_render.js`, `form_theme.css`, `hljs_1c_xml.js`).
- `tests/` — интеграционные тесты, эталонный синтетический донор `tests/fixtures/donor.epf` (все 27 типов элементов обычных форм 1С 8.2) и golden-корпус (`tests/golden/`).
- `docs/` — документация: единый план и долг проверки (`docs/todo.md`), реестр проверенного (`docs/agent-readiness.md`), руководство агента (`docs/agent-guide.md`), справочник тегов (`docs/xml-reference.md`); устаревшие планы — в `docs/archive/`.
