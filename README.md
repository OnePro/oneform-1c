# oneform

`oneform` — однофайловая программа командной строки (Rust, Windows и macOS) для работы с **обычными формами 1С:Предприятие 8.2 / 8.3**: внешние обработки (`.epf`), формы справочников, документов и других объектов из XML-выгрузки конфигурации, формы внешних отчётов из XML-выгрузки платформы.

Что она делает по существу:

* превращает бинарную форму (`Form.bin`, форма в `.epf`) в читаемые файлы: `Form.xml`, `FormModule.bsl`, `ObjectModule.bsl` и приблизительную картинку формы `FormPreview.html`, чтобы **разрабатывать и ревьюить** форму как обычный код (git-diff, поиск, чтение модулей);
* записывает изменения обратно в `.epf` или `Form.bin`, сохраняя нетронутые байты;
* проверяет раскладку и сообщает, можно ли форму править безопасно.

Программе не нужны платформа 1С, Python и внешние библиотеки: ассеты просмотрщика встроены в исполняемый файл.

## Статус возможностей

**Читайте это до работы с `pack`.**

| Статус | Что входит |
|---|---|
| **Стабильно** (основной режим) | `extract` (`Form.xml`, `FormModule.bsl`, `ObjectModule.bsl`, `FormPreview.html`, `.oneform/index.html`); `validate`; `lint`; `preview`; `check`; `diagnose`; `history` (`list` / `diff` / `restore`); `feedback`; **правка текста модулей** (`FormModule.bsl`, `ObjectModule.bsl`) с записью через `pack` |
| **Экспериментально** (нужен флаг `--experimental`) | любое изменение, при котором `pack` перезаписывает поток формы (`Form.bin`) по правкам `Form.xml`: свойства существующих элементов, добавление, удаление и перенос элементов, панели и страницы, командные панели и кнопки, таблицы значений и их колонки, реквизиты формы, шрифты и цвета, заголовок и размер формы; запись `FormStream.bin` и шаблонов (`Template.html`, `Template.bin`); команды `new-form` и `clone-form` |

**Защита в программе.** `pack` без `--experimental` пишет только текст модулей. Если в плане есть что-то ещё (правки `Form.xml`, меняющие поток формы, `FormStream.bin`, шаблоны), он отказывает целиком и до любой записи с кодом `EXPERIMENTAL_REQUIRED` (код возврата 2) и объясняет, что было бы записано. `pack --dry-run` работает без флага и помечает такие правки строкой `EXPERIMENTAL:`. `new-form` и `clone-form` без флага тоже отказывают. Флаг включается только явно: переменной окружения его включить нельзя. Это явная метка и защита от случайного запуска, а не замок: правило «только по подтверждению пользователя» для агентов остаётся (см. ниже).

Экспериментальная запись может завершиться успешно, а 1С форму не откроет: это подтверждено на практике. Применяйте её только сами и только понимая последствия; ИИ-агентам разрешено использовать её **лишь по явному подтверждению пользователя в текущем разговоре**. Перед записью проверьте, что есть git-ветка или копия, и откройте результат в 1С. Известные дефекты записи и обходные пути: таблица «Известные дефекты экспериментальной записи» в [`docs/experimental-form-editing.md`](docs/experimental-form-editing.md), задачи — в [`docs/todo.md`](docs/todo.md).

Перечень возможностей ниже описывает, что программа умеет, но не гарантирует, что 1С откроет форму после экспериментальной записи. Что проверено в живой 1С, а что только тестами — в реестре [`docs/agent-readiness.md`](docs/agent-readiness.md).

### Область применимости

Вне плана и не поддерживаются: формы платформы 8.0 (версия потока меньше 24; доступен только модуль), элемент `ActiveXControl`, формы с повторяющимися именами элементов, нестандартные формы. Команда `oneform validate` определяет это по каждой форме: `IN_SCOPE` или `OUT_OF_SCOPE` с кодом причины (`format-8.0`, `metadata-layout`, `unsupported-control`, `duplicate-name`, `round-trip-differs`, `unreadable`). Проверяйте форму через `validate` до любой работы с ней.

Формы со старой версией потока (25 и 26: часть форм УТ 10.3) читаются, но в них допускается добавлять только `Label`, `InputField`, `CheckBox`, `Button`. Что говорить пользователю в этом случае, описано в [`docs/agent-guide.md`](docs/agent-guide.md), раздел «Форма старой версии потока (25 / 26)».

## Установка

**Готовые сборки.** В релизах репозитория (GitHub Releases) лежат архивы `oneform-<версия>-windows-x64.zip`, `oneform-<версия>-macos-arm64.tar.gz`, `oneform-<версия>-macos-x64.tar.gz` и `SHA256SUMS.txt`. В архиве: `oneform` (`oneform.exe`), `INSTALL.txt`, `README.md`, `docs/agent-guide.md` (стабильный режим), `docs/experimental-form-editing.md` (экспериментальная запись раскладки), `skills/` (три навыка для ИИ-агента). Положите исполняемый файл в каталог из `PATH` и проверьте `oneform --help`.

* macOS: файл не подписан Apple. Если система не запускает его: `xattr -d com.apple.quarantine ./oneform`. Сборки macOS получены кросс-компиляцией и в CI, полная проверка на реальном Mac не проводилась.
* Навыки агента (`skills/oneform-forms`, `skills/oneform-forms-experimental`, `skills/oneform-form-design`) скопируйте в каталог навыков вашего агента (`%USERPROFILE%\.agents\skills` на Windows, `~/.agents/skills` на macOS).

**Из исходников** (нужен Rust stable, см. `rust-toolchain.toml`):

```bash
cargo build --release --locked      # target/release/oneform (oneform.exe)
cargo test --locked                 # модульные, фикстурные и golden-тесты (платформа 1С не нужна)
```

## Быстрый старт

`oneform` принимает **каталог**, а не файл: `oneform validate X.epf` даёт ошибку, нужно `oneform validate <каталог с X.epf>`.

```bash
oneform validate <PATH>        # можно ли работать с формой: IN_SCOPE / OUT_OF_SCOPE
oneform extract  <PATH>        # src/Forms/<Форма>/Form.xml, FormModule.bsl, FormPreview.html; просмотрщик .oneform/index.html
# правите src/Forms/<Форма>/FormModule.bsl (стабильно) ...
oneform pack <PATH> --dry-run  # что изменится; причина отказа, если не получится
oneform pack <PATH>            # запись (без --experimental — только текст модулей); прежнее состояние формы сохраняется само в .oneform/history
oneform lint <PATH>            # проверка раскладки Form.xml
```

Если правился `Form.xml` (экспериментальный режим), нужны `pack --dry-run`, затем `pack --experimental`; результат обязательно откройте в 1С.

Для `.epf` каталог `src/` создаётся рядом с файлом. Для объекта конфигурации (`Forms/<Форма>/Ext/Form.bin`) — в каталоге объекта. После `pack` откройте форму в 1С и проверьте её.

## Команды

| Команда | Что делает | Пишет файлы |
|---|---|---|
| `extract <PATH>` | находит `.epf` и `Ext/Form.bin`, создаёт `src/` с `Form.xml`, модулями, `FormPreview.html`, `ExtractionManifest.json`, шаблонами; строит `.oneform/index.html` (просмотрщик всех форм) | да (`src/`, `.oneform/`) |
| `pack <PATH> [--dry-run] [--backup] [--experimental]` | без флага записывает только текст модулей (`FormModule.bsl`, `ObjectModule.bsl`) в `.epf` и `Form.bin`; с `--experimental` также переносит правки `Form.xml`, `FormStream.bin` и шаблонов в поток формы; перед записью проверяет результат повторным чтением; сохраняет снимок в `.oneform/history` | да |
| `check <PATH>` | `src/` соответствует бинарным источникам? Код 0 — да, 3 — есть расхождения | нет |
| `preview <PATH>` | пересобирает `FormPreview.html` и `.oneform/index.html` | да |
| `lint <PATH> [--json] [--strict]` | проверка раскладки: за краем формы, наложения, отсутствие растягивания, нижняя панель, порядок обхода, отклонения от обычных значений вида формы | нет |
| `validate <PATH> [--json]` | `IN_SCOPE` / `OUT_OF_SCOPE` по каждой форме с причиной | нет |
| `history [PATH]`, `history diff [PATH] [id]`, `history restore [PATH] <id>` | список снимков, разница `before/after`, откат (текущее состояние сохраняется как новый снимок) | `restore` — да |
| `diagnose [PATH] [--json]` | последние отказы и предупреждения, последний снимок, статус `validate`, куда читать, команды на случай «форма не открылась в 1С» | нет |
| `feedback add [PATH]`, `feedback list`, `feedback show <id>` | отчёт об ошибке или пожелании с текстом ошибки 1С, снимком и результатами проверок | `add` — да (`.oneform/feedback/`) |
| `new-form <каталог объекта> --kind … --name … --experimental` | новая пустая обычная форма (**экспериментально**, без флага отказ) | да |
| `clone-form <каталог объекта> --from … --name … --experimental` | копия формы объекта конфигурации (**экспериментально**, без флага отказ) | да |

Общие параметры: `-j/--workers N` (по умолчанию 3), `--dry-run`, `--json`, `--no-progress`. Параметр `--experimental` допустим только для `pack`, `new-form`, `clone-form`; для остальных команд это ошибка использования. Коды возврата: `0` — успешно, `1` — сбой, `2` — ошибка использования или `EXPERIMENTAL_REQUIRED`, `3` — расхождения (`check`; `lint --strict` при предупреждениях). Полный список: `oneform --help` (команды разделены на блоки «стабильные» и «экспериментальные»).

Бинарный отчёт `.erf` напрямую не читается: команды его пропускают и сообщают об этом. Для отчёта используйте XML-выгрузку платформы (навык `erf-dump`), после правок — сборку (`erf-build`).

## Что получается после `extract`

* `Form.xml` — структура формы (элементы, свойства, привязки, события, панели, командные панели, таблицы, реквизиты). Описание тегов: [`docs/xml-reference.md`](docs/xml-reference.md).
* `FormModule.bsl`, `ObjectModule.bsl` — модули с сохранением исходной кодировки и переводов строк.
* `FormPreview.html` — **приблизительная** картинка формы в одном автономном HTML-файле (положения и размеры берутся из `Form.xml`, вид приближен к 1С по эскизам дизайнера и эталонным снимкам, но это не пиксельно точная копия). Интерактивный инспектор: выбор элементов, кнопок командных панелей, колонок, строк таблиц, переход от события к процедуре модуля с подсветкой синтаксиса. Работает офлайн.
* `.oneform/index.html` — общий просмотрщик всех форм в каталоге.
* `ExtractionManifest.json`, `ExtractionReport.md` — что создано и контрольные суммы; по ним `check` и `pack` определяют, не менялись ли файлы вне вашего контроля.

## Запись (`pack`)

* **Стабильно (без флага):** запись текста модулей. Остальные части формы не затрагиваются и сохраняются байт в байт.
* **Экспериментально (только с `--experimental`):** перенос правок `Form.xml` в поток формы. Известные дефекты — в таблице «Известные дефекты экспериментальной записи» в `docs/experimental-form-editing.md` (в частности, правка шрифтов существующих элементов ломает форму, новая командная панель в форме `.epf` не открывается в 1С). Что программа берёт на себя: правка свойств, добавление элементов из вшитых прототипов (26 из 27 видов; `ActiveXControl` вне плана), привязка полей и таблиц к реквизитам и табличным частям, удаление элементов вместе с поддеревом, панели со страницами, командные панели, реквизиты и таблицы значений. Чего она не может определить сама, программа показывает **предупреждением** (ссылки на удалённые элементы в коде модуля, осиротевшие обработчики, элемент вне контейнера и т. п.), а то, чего не умеет, **отклоняет** с понятной ошибкой (`FORM_EDIT_REJECTED`, `unsupported-*`), не меняя файлы.
* **Защита.** Перед записью `pack` повторно декодирует результат и сверяет его с запрошенным; пишет транзакционно. Каждая успешная запись, меняющая форму, сохраняет прежнее состояние в `<каталог объекта>/.oneform/history/<время>-<форма>/` (последние 20, переменная `ONEFORM_HISTORY_KEEP`, `0` — выключить). `history restore` возвращает прежнюю форму. Ограничение защиты: проверка читает поток нашим же разборщиком, поэтому она **не гарантирует, что 1С его примет**.
* `--backup` дополнительно сохраняет `.bak` прежнего `.epf` или `Form.bin`.
* **Метка в данных.** Успешная экспериментальная запись печатает строку `EXPERIMENTAL`, а в манифесте снимка истории, журнале диагностики, `diagnose` и отчёте `feedback add` стоит `experimental: true`: сразу видно, что форму менял экспериментальный режим.
* **Windows: занятые папки.** Если антивирус или наблюдатель за файлами (редактор кода, анализатор) на время занял папку, программа повторяет операцию с паузами; если папку держат постоянно, обновляет файлы внутри неё и выводит предупреждение `updated in place`.

## Для ИИ-агентов и разработки в репозитории

* Руководство агента, стабильный режим: [`docs/agent-guide.md`](docs/agent-guide.md) (правило для агента, цикл работы, область применимости, правка текста модулей, история и обратная связь, отказы). Экспериментальная запись раскладки: [`docs/experimental-form-editing.md`](docs/experimental-form-editing.md) (таблица известных дефектов, допустимые правки `Form.xml`, `new-form`, `clone-form`, рецепты). Агент передаёт `--experimental` только после явного подтверждения пользователя в текущем разговоре. Навыки: [`skills/oneform-forms`](skills/oneform-forms/SKILL.md) (стабильно: чтение форм, модули, проверки), [`skills/oneform-forms-experimental`](skills/oneform-forms-experimental/SKILL.md) (запись раскладки, только по подтверждению) и [`skills/oneform-form-design`](skills/oneform-form-design/SKILL.md) (числа и рецепты раскладки по стандартам 1С; проверка стабильна, применение экспериментально).
* **Цикл в репозитории.** Рядом с `.epf` лежит git-репозиторий; в git кладут `.epf` и, если хотят читать формы в diff, `src/`; в `.gitignore` — `.oneform/` и `.extract-work/`. В `.oneform/` программа хранит историю снимков, журнал диагностики (`diagnostics.jsonl`, только метаданные, без содержимого файлов) и отчёты обратной связи.
* **Обратная связь.** Если `pack` отказал и это мешает, предупреждение неверно или 1С выдала ошибку: `oneform diagnose`, затем `oneform feedback add --history <id> --1c-error "<точный текст ошибки 1С>" --note "<что делали>"`. Отчёт может содержать тексты модулей (токены, пароли): прочитайте его перед передачей; бинарные файлы добавляются только с `--include-binaries`. Если задана `ONEFORM_FEEDBACK_DIR`, отчёт копируется и туда.

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `ONEFORM_CONFIG_ROOT` | каталог XML-выгрузки конфигурации: по нему `pack` определяет ссылочные типы в `.epf` (если не задана, ищется конфигурация вокруг `.epf`) |
| `ONEFORM_HISTORY_KEEP` | сколько снимков истории хранить на объект (по умолчанию 20, `0` — не сохранять) |
| `ONEFORM_DIAG_CAP` | сколько строк журнала диагностики хранить (по умолчанию 500) |
| `ONEFORM_FEEDBACK_DIR` | копировать отчёты `feedback add` в этот каталог |
| `ONEFORM_FS_RETRY_MS` | общий бюджет повторов при временной блокировке файлов на Windows, мс (по умолчанию около 1500, `0` — без повторов) |
| `ONEFORM_CARRIERS` | `1` — `extract` дополнительно пишет исходные бинарные записи (для генераторов форм) |
| `EPF_OOF_PATH` | необязательный внешний `oof` (то же, что `--oof-path`) |

## Исследовательские инструменты

Служебные подкоманды для изучения формата; обычной работе не нужны.

```bash
oneform props <FormStream.bin|Form.bin> [--control <Имя>] [--diff <Other.bin>]   # дамп и побайтовый diff дерева свойств элемента
oneform explore mutate --spec <exp.json> --stream <FormStream.bin> --out <dir>   # точечная мутация одного слота потока
oneform explore candidates --stream <FormStream.bin> --control <Имя>             # кандидатные флаговые слоты
oneform explore run --matrix <spec.json|dir> --epf <donor.epf> --base <infobase> --platform <bin-1cv8> [--corpus <dir>]
```

`explore run` прогоняет baseline и мутации через платформу 1С (нужна установленная платформа и база-копия). Корпус воспроизводится тестом `tests/explore_corpus.rs` без платформы; регенерация через платформу — только явным включением (`ONEFORM_EXPLORE=1`, `ONEFORM_EXPLORE_BASE`, `ONEFORM_EXPLORE_PLATFORM`). Находки по слотам свойств: [`docs/property-exploration.md`](docs/property-exploration.md).

## Разработка и выпуск

Команды `just` (файл `justfile`):

| Команда | Что делает |
|---|---|
| `just build`, `just test`, `just clippy` | сборка, тесты, линтер |
| `just extract/pack/preview/check [DIR]` | запуск собранного `oneform` |
| `just dist` | архив релиза для текущей машины в `target/release-dist/` |
| `just dist-mac [arm64\|x64\|both]` | сборка и упаковка macOS без Mac (нужны Zig и `cargo-zigbuild`) |
| `just release [ВЕРСИЯ]` | тесты, тег `v<версия>`, push; GitHub Actions собирает Windows и macOS и публикует релиз с архивами и `SHA256SUMS.txt` |
| `just release-local [ВЕРСИЯ]` | то же без CI: Windows собирается локально, macOS через Zig |
| `just release-dry` | показать, что сделает релиз, ничего не меняя |

CI (`.github/workflows/ci.yml`) прогоняет тесты и `clippy` на Windows и macOS; сборку релиза выполняет `.github/workflows/release.yml`.

Правила разработки: байты, которых правка не касается, сохраняются; `cargo test --locked` проходит без платформы 1С; `cargo clippy --locked --all-targets` без замечаний; golden-эталоны меняются только осознанно (`GOLDEN_BLESS=1`). Изменения по спецификациям (OpenSpec) в репозиторий не входят.

### Структура репозитория

* `src/` — CLI и библиотека: разбор контейнеров 1С v8, декодер потока формы, генератор `Form.xml`, упаковщик (транзакционный), проверки (`lint`, `validate`), история, диагностика, просмотрщик.
* `assets/` — вшитые в бинарник ассеты просмотрщика (`form_render.js`, `form_theme.css`, `hljs_1c_xml.js`).
* `tests/` — интеграционные тесты, образцы (`tests/fixtures/`, в том числе `donor.epf` со всеми видами элементов), golden-эталоны (`tests/golden/`).
* `docs/` — документация (см. ниже); `docs/evidence/` — доказательства проверки в живой 1С; `docs/design/` — проектные записки и пакет для дизайнера превью (`docs/design/preview-designer/`).
* `skills/` — навыки ИИ-агента (копируются в архив релиза).
* `scripts/` — служебные скрипты: упаковка и выпуск релиза, проверка геометрии превью, генераторы каталога свойств, фаззинг на корпусах, проверка доказательств.
